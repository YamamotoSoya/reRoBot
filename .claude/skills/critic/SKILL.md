# Critic — 結論を書く前に必ず一人の反対者を通す

主担当 (自分) が出した結論を、反証専任の subagent `critic` に**逆の前提**で検証させる。
「同じ結論を書いた文書が多いこと」を証拠扱いしてしまった 2026-08 の縦角説の再発防止。

## いつ起こすか (デフォルト = 自動、ユーザ確認不要)

| 局面 | 起こす |
|---|---|
| docs/issue のステータスを「原因特定済み」「本命」「確定」にする前 | **必須** |
| PROJECT_STATE の「既知の問題」「次にやること」で優先度を動かす原因判断 | **必須** |
| debug-report / feature-doc の「原因」「設計判断」節を書く前 | **必須** |
| 2 つ以上の docs が同じ原因を指していて、それを根拠に次の作業を決めるとき | **必須** (連鎖を切る) |
| ユーザが `/critic <結論>` と打ったとき | 手動 |
| 単純な事実確認・ビルドエラー・typo 修正 | 不要 |

## 手順

1. 結論を 1〜3 行に固定し、信頼度の自己申告を付ける (確定 / 本命 / 傍証のみ)。
2. `Agent` ツールで `subagent_type: "critic"` を 1 体起こす。**`.claude/agents/` の定義はセッション開始時に読まれる**ので、
   同じセッション内で新設・変更した直後は `Agent type 'critic' not found` になる。その場合は
   `subagent_type: "general-purpose"` で起こし、`.claude/agents/critic.md` の本文をプロンプト先頭に貼って役割を与える
   (ツールは読み取り専用に限る旨を明記)。プロンプトの型:
   ```
   結論: <1〜3 行>  (種類: 原因特定 / 設計判断 / 仮説採択)
   自己申告の信頼度: <確定 / 本命 / 傍証のみ>
   証拠の所在: <docs/issue/... , bags/.../dump, 数値表>
   既に棄却した仮説とその根拠: <箇条書き>
   判断が変わると何が変わるか: <次の作業・時間・機械負荷>
   制約: 読み取り専用。GLIM 等の重い処理は提案のみ (この機械は 16 GB RAM、OOM 再起動歴あり)。
   ```
3. 返答を受けたら:
   - 判定が自己申告より低ければ **docs の表現を判定に合わせて下げる** (「確定」→「本命」等)。
   - 「棄却実験」のうち**最も安いもの**が 10 分以内で回るなら、その場で実行して結果を結論に反映する。
     回せないなら docs の「次の一手」に実験として残す。
   - 棄却できなかった代替仮説は、結論と**同じ文書の同じ節**に列挙する (別ファイルに追いやらない)。
4. 返信のユーザ向け要約に「critic の判定: <判定>、残る代替仮説: <n 件>」を 1 行入れる。

## 出力の扱いの原則

- critic に同意する義務はない。ただし**反論するなら証拠 (数値・パス) を示す**。
- critic の「識別力がある証拠 / 傍証にとどまる証拠」の仕分けを docs に転記する。読者が
  どこまで確かめられているかを一目で分かるようにするため。
- critic が「もっと調べろ」だけを返したら、具体的な棄却実験を書き直させる (SendMessage で続ける)。

## 事例 (2026-09-10)

結論「GLIM z ドリフト = 縦角表誤差」に対し、critic 相当の検証で:
- 識別力あり: 縦角補正 / 4 倍悪化で z 不変 (因果)・z の途中反転・屋内で消失・物理上限 2 桁不足 → **棄却**
- 傍証にとどまっていた: 「ヨー 180° で符号反転」(45° 側が別原因の照合縮退で交絡)・床メトリクスの不揃い (縦角誤差の存在は示すが z ドリフトとの因果は示さない)
- 生き残った本命: SLAM 側の z/ピッチ観測性 × 旋回時 submap 姿勢誤差 (信頼度 = 本命、因果未確認)
詳細 `docs/issue/2026-09-10_glim_z_drift_not_vangle.md`。
