# Annotate

Claude の返信に出てくる発展的なコマンドや専門用語を、ユーザのレベルに合わせて
注釈する。目的は「作業は進むが用語が分からないまま」を防ぐこと。
`knowledge-check` (実装理解の確認) の日常版にあたる。

## いつ使うか

- **常時**。毎返信に適用する (CLAUDE.md の作業慣例から参照される)。
- 注釈の書式・レベル基準に迷ったとき、既知用語リストを更新するときに本ファイルを開く。

## 注釈の書式

- 本文中の対象語の直後に `※1`, `※2`, … のマーカーを付ける。
- 返信の**最後**に `📘 注釈` ブロックを置き、番号順に解説する。
- 1 用語 = 1〜2 行。「何であるか」+ できれば「このプロジェクトでなぜ使うか」。
- 1 返信あたり**最大 3 個**。候補が 4 個以上あれば、作業の理解に効く順で絞る。
- 注釈が 1 つも無い返信にはブロック自体を付けない。

例:

> ビルド後は `install/setup.bash` を source※1 してください。
>
> 📘 注釈
> ※1 `source` — スクリプトを現在のシェル内で実行し、環境変数の変更を
>    今のシェルに反映させる bash 組み込み。普通に実行すると子シェルで
>    変わるだけで消える。

## レベル基準

初期較正は `docs/claude/USER_LEVEL.md` (git 管理外のレベルプロファイル) に従う —
「既知」帯は注釈しない、「未習」帯は優先的に注釈する。下の固定基準とプロファイルが
食い違ったら**プロファイル優先** (そちらの方が新しい証拠で較正されている)。
プロファイルが無い環境では下の固定基準だけで運用する。

**注釈しない** (既知とみなす):

- ROS 2 基礎: node / topic / launch / param / colcon / rviz
- git 基礎: clone / branch / commit / push / merge
- Docker 基礎: container / image / compose / bind mount
- このプロジェクトの日常語: CAN / CANopen / EPOS4 / PDO / SDO / odometry / teleop /
  LiDAR / IMU / SLAM
- 下の「既知用語リスト」に載っている語

**注釈する**:

- 発展的シェルコマンド・記法: `xargs`, `awk`, `sed -i`, `trap`, `tee`, `flock`,
  `2>&1`, プロセス置換 `<()` など
- git 発展: `rebase`, `cherry-pick`, `reflog`, `stash`, `bisect`, gitlink,
  detached HEAD など
- Linux 内部: udev, systemd unit, netns, capability, cgroup など
- CS 一般用語: race condition, mutex, デッドロック, RAII, quaternion の数理,
  コールバックグループなど
- ROS 2 発展: QoS の詳細 (reliability/durability), lifecycle node, executor,
  DDS, composable node など

**迷ったら注釈する**。知っている語の注釈は読み飛ばせるが、知らない語の欠落は
埋まらない。

## 既知用語リストの運用 (自己調整)

- ユーザが「それは知ってる」「〜の注釈いらない」と言ったら、その用語を下の
  リストに Edit で**その場で追記**する。以後その語は注釈しない。
- 逆にユーザが「〜って何?」と聞いた語は、リスト外なら次回から注釈対象に含める
  (レベル基準の較正材料として扱う)。
- リストは 1 行 1 語、アルファベット順を保つ。追記時に一言「既知リストに
  追加しました」と報告する。
- まとまった追記 (目安 3 語) が溜まったら `/user-level` スキルで
  `docs/claude/USER_LEVEL.md` のレベル表へ反映する (個々の語→分野レベルへの昇華)。

## 守るべきこと

- 注釈は事実のみ簡潔に。うんちくで膨らませない。
- 本文の説明責務を注釈に逃がさない — 注釈を読まなくても本文だけで意味が
  通る文を書く。注釈は「深く知りたい人向けの補足」。
- このファイルの編集は**既知用語リストへの追記のみ**。書式・レベル基準の変更は
  ユーザの指示があったときだけ。
