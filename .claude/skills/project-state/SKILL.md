# Project State

`docs/claude/PROJECT_STATE.md` は次の Claude セッションに現在地を渡すメモリファイル。
このスキルは、セッションで起きた状態変化をそこへ反映する。

## いつ使うか

- 大きな状態変化があったセッションの終了時 (機能追加・重要バグの解決・方針変更・
  実機検証の成否判明)
- ユーザが「PROJECT_STATE を更新して」「状態メモに反映して」等と要求したとき

小さな変更 (typo 修正、ドキュメントのみの変更) では更新しない。ノイズが増えると
メモリファイルとしての価値が下がる。

## 手順

1. **PROJECT_STATE.md を全文 Read** する (前回更新からの前提が変わっていないか確認)。

2. **セッションの成果を分類**する:
   - 到達点の変化 → §4「何がどこまで動いているか」
   - 問題の新規発見・解決 → §5「既知の問題」(docs/issue のステータスと整合させる)
   - 出来事 → §6「タイムライン」に 1 行追記
   - 罠になる知見 → §7「コードを触るときに知らないと踏む罠」(本当に罠のときだけ)
   - 作業計画の変化 → §10「次にやること」

3. **該当セクションだけを Edit** する。冒頭の `最終更新` 日付と「時点」の説明も更新する。

4. **更新内容の要約をユーザに報告**する (どのセクションに何を足した/消したか)。

## 守るべきこと

- **Write での丸ごと上書きは禁止**。必ず Edit で該当箇所のみ変更する。ファイル全体の
  再生成は、過去の経緯 (§6・§7) を静かに壊す。
- **§1〜3・§7〜9 の安定セクションは事実が変わったときのみ**触る。ハードウェア構成
  (§2) の変更は実機で確認された場合だけ反映する。
- **「動く (実機検証済み)」への昇格は実機確認があったときだけ**。ビルドが通った・
  シミュレーションで動いた、は「構成はあるが未完/未接続」止まり。
- `docs/monthly/` は**ユーザの月次ゼミ報告で Claude は編集禁止** (読み取り専用の入力)。
  monthly の内容を根拠に状態を更新するのは可。
- 推測で状態を書かない。「〜の疑い」「未検証」はその旨を明記して残す (既存の書き方に
  倣う)。
