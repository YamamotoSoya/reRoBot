# Textbook

特定テーマ (例: タイムスタンプ、TF、QoS、CAN 通信) を基礎から体系的に学べる
書籍風ドキュメントを `docs/text/<topic>/` に作る。debug-report が「1 つの事故の記録」、
feature-doc が「1 つの機能の記録」なのに対し、こちらは**テーマを横断する教材**。
ユーザの「仕組みがわからないまま作業が進む」を根本から埋めるためのもの。

## いつ使うか

- ユーザが「書籍化して」「体系的にまとめて」「教科書っぽく解説して」と言ったとき
- 1 テーマ = 1 ディレクトリ `docs/text/<topic>/` (topic は英小文字 snake_case)
- 単発の質問への回答で足りるなら使わない (チャットで答える)。同じテーマの質問が
  繰り返される・事故が複数件溜まっている、が書籍化のサイン

## 手順

### 1. 材料収集 (執筆前に必ず)

- テーマに関わる**実コードの位置 (file:line) と短い引用**を Explore agent で確定する。
  行番号は執筆直前の状態で取ること (古い文書の行番号はドリフトしている前提で再確認)
- 一次資料を洗う: `docs/issue/` `docs/report/` `docs/claude/PROJECT_STATE.md` の関連記録。
  事例集の章はここから作る
- 既存の解説 (`docs/claude/knowledge/` 等) と重複しそうな箇所は、どちらを正とするか
  決めて相互リンクする

### 2. ユーザ確認 (AskUserQuestion で 2 点だけ)

1. **ファイル構成**: 章ごとに分割 (推奨・既定) / 1 ファイル
2. **軸足**: 一般論の教科書 (推奨・既定。他プロジェクトでも読み返せる) /
   本プロジェクト特化。どちらでも「一般論 + 実コード事例」の両方は入る

### 3. 章構成の型

`template.md` の骨格に従う。標準は 00_index + 6〜7 章、総量 1,000〜1,600 行
(1 章 150〜300 行)。章の並びは**積み上げ順**にする:

```
00_index ........ 目次樹形図・読み方・凡例・一次資料リンク
├── 基礎編 (1〜2 章) .... 概念の「器」と構造。一般論。樹形図多め
├── 使い方編 (1〜2 章) .. 書く側/作る側の記法テンプレ + アンチパターン表
├── 仕組み編 (1 章) ..... 読む側/消費する側の機構。「誰がそれを信じているか」
├── 適用編 (1 章) ....... 本プロジェクトでのあるべき姿と現在地のギャップ分析
├── 事例集 (1 章) ....... 実際に起きた事故の解剖 (下記の型)
└── 実務編 (1 章) ....... チェックリスト・診断コマンド・症状からの逆引き表
```

- 「初読は順に、急ぐなら事例集から」のような**複数の読み進め方**を 00_index に書く
- 各章末に「→ 次章」リンク。章間参照は本文にも積極的に張る

### 4. 執筆規則

- **樹形図を主役にする** (ユーザの好み。構造・分類・選択フローは樹形図で描く)。
  mermaid は「流れ」の説明 (時系列・シーケンス・写像) に使い、
  `graph TD` / `flowchart LR` / `sequenceDiagram` の基本記法のみ
  (mindmap 等の新記法は GitHub で描画されない)。タイムラインのずれは ASCII 図が有効
- **章間リンクはファイル単位** (`[第3章](03_xxx.md)`)。フラグメント (#) を使うのは
  `## 事例A` のような**短い見出し**だけ。`{#custom-anchor}` 記法は GitHub 非対応なので禁止
- 実コード引用は `path/to/file.cpp:123` 形式 + 「行番号は YYYY-MM-DD 時点」を凡例に明記
- 事例の解剖は必ず **症状 → 機構 → 修正 → 教訓** の 4 部構成。章冒頭に
  「事例 | 一言 | 破った原則 | 状態」のサマリ表を置く
- 各ファイル先頭に `<!-- claude: ... -->` コメントタグ (作成日・経緯 1 行)
- 説明は「なぜそうなるか」まで書く (CLAUDE.md の方針)。数字で示せる影響は数字で
  (例: 「0.16 s のずれ = IMU 16 サンプル分 = 旋回 90°/s なら ~14°」)

### 5. 検証 (執筆後に必ず)

1. **リンク存在チェック**: `grep -rhoE '\]\([0-9a-z_]+\.md' docs/text/<topic>/ | sort -u`
   で列挙し、全ファイルが実在するか確認
2. **行番号の再 grep**: 引用した file:line を最終稿で再確認する。
   ⚠️ 特に**同じセッションで自分がそのコードを変更した場合**、執筆時の記憶より
   行がずれている (timestamp 読本では自分の修正で +12 行ずれた)
3. mermaid ブロックが基本記法だけか目視確認
4. `wc -l` で総量が目安内か確認

### 6. 完了後

- CLAUDE.md の docs 表・PROJECT_STATE のタイムラインに反映する
- ユーザには VS Code プレビュー (`Ctrl+Shift+V`) で mermaid 込みで読めることを案内

## 守るべきこと

- 書籍でも本文の説明責務は本文で果たす — 注釈・リンク先に逃がさない
- 事例集は一次資料 (issue/report) への参照を必ず付け、書籍側で事実を改変しない。
  未解決のものは「潜在欠陥として残存」と正直に書く
- テーマの切り出しは「1 冊で完結する粒度」に。大きすぎるテーマ (例:「ROS 2 全部」)
  は分冊を提案する
