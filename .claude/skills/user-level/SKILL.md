# User Level

ユーザの知識レベルに関する証拠を集約し、プロファイル `docs/claude/USER_LEVEL.md` を
更新する。プロファイルは annotate (注釈レベル) と knowledge-check (出題難易度) の
共通の較正元になる。

## 前提: プロファイルは個人情報

- `docs/claude/USER_LEVEL.md` は **git 管理外** (.gitignore 登録済み)。
  **コミット・push は絶対にしない**。`git add -A` でも入らないが、`-f` 付き add は禁止。
- このスキルファイル自体はコミットされるので、**ここに推定内容 (個人データ) を書かない**。
  手順とパスだけを書く。
- 別マシンのクローンでプロファイルが存在しない場合は、本スキルの手順で新規作成する
  (構成は既存ファイルの §1〜§3 に倣う。無ければ本スキル末尾の骨子を使う)。

## いつ使うか

- knowledge-check を実施した後 (クイズ正誤という強い証拠が出る)
- annotate の既知用語リストにまとまった追記 (目安 3 語) があったとき
- `docs/monthly/` に新しい月次報告が追加されたとき
- ユーザが「レベル推定を更新して」「私の知識レベルは?」等と要求したとき

## 手順

1. **情報源をすべて読む**:
   - `docs/claude/USER_LEVEL.md` (現在の推定と §2 較正ログ)
   - `docs/monthly/` の全ファイル (本人の文章。自力でやったこと/理解不足の自己申告の両方を拾う)
   - `docs/claude/knowledge/` の全記録 (クイズの正誤・弱点メモ)
   - `.claude/skills/annotate/SKILL.md` の既知用語リスト
   - 今セッション中の本人発言 (「知ってる」「〜って何?」)

2. **現在の §1 レベル表と食い違う証拠を列挙**する。証拠には必ず出典
   (ファイル名 + 節、または「YYYY-MM-DD の発言」) を付ける。

3. **USER_LEVEL.md を Edit で更新**する:
   - §1 の該当行のレベル・根拠・更新日を直す (行の丸ごと書き換えは可、ファイルの Write 上書きは禁止)
   - §2 に較正イベントを 1 行追記
   - 冒頭の最終更新日を直す

4. **変更点をユーザに報告**し、推定が本人の実感と合っているか確認を促す。
   本人の訂正はその場で §1 に反映し、§2 に「本人申告」として記録する。

## 守るべきこと

- **1 つの証拠で急にレベルを上下させない**。既知⇄未習の 2 段跳びは本人申告のみ可。
- **クイズの誤答は「未習」ではなく「実践中の弱点」として記録**する。減点主義にしない
  (knowledge-check の方針と同じ)。
- **本人申告 > 推定**。推定と申告が食い違ったら申告に合わせ、根拠欄に「本人申告」と書く。
- `docs/monthly/` は読み取り専用の入力。編集禁止。
- 推定の根拠を書かない行を作らない (根拠のない推定は較正できない)。

## プロファイルの骨子 (新規作成時のみ使用)

```markdown
<!-- claude: ユーザの知識レベルプロファイル。個人情報のため git 管理外。コミット禁止。-->
# ユーザ知識レベルプロファイル
- **最終更新: YYYY-MM-DD**
- レベル凡例: 既知 / 実践中 / 未習

## §1 分野別レベル表
| 分野 | 推定レベル | 根拠 (出典) | 更新日 |

## §2 較正イベントログ (追記式)
| 日付 | 出来事 | 反映 |

## §3 更新ルール
(Edit のみ・本人申告優先・情報源一覧 — 既存運用に倣う)
```
