# Explain Edits

Claude がファイルを変更する (チャット上で `Update(...)` / `Write(...)` と表示される
ツール呼び出しを行う) とき、その**直前の本文テキストで変更内容を数行で説明**する。
目的は「気づいたらコードが変わっていて、何が起きたか追えない」を防ぎ、ユーザが
diff を読む前に変更の意図を把握できるようにすること。`annotate` (用語注釈) の
コード変更版にあたる。

## いつ使うか

- **常時**。コード・設定・launch など、リポジトリ内のファイルを Edit / Write /
  NotebookEdit で変更するたびに適用する (CLAUDE.md の作業慣例から参照される)。
- 書式・粒度に迷ったときに本ファイルを開く。

## 書式

各ツール呼び出しの**直前**に、以下を 1〜4 行で書く:

1. **どこを** — 対象ファイルと変更箇所 (関数名・パラメータ名など)。
2. **何を** — 変更の内容 (追加 / 修正 / 削除と、その中身)。
3. **なぜ** — その変更が必要な理由・期待する効果。CLAUDE.md の方針
   「なぜそうなるか」まで書く、に従う。

例:

> `epos4_odometry.cpp` の `syncCallback` を修正します。twist の計算を
> `joint_states.velocity` 参照から位置差分 (Δposition/Δt) に置き換えます —
> ドライバの velocity は 0x606C が PDO 未マップのため常に 0 で、
> このままだと EKF に速度が入らないためです。
>
> (ここで Edit ツール呼び出し)

## 粒度の基準

- **1 呼び出し = 1 説明**。連続する複数の Edit をまとめて先頭で説明してもよいが、
  その場合はどの説明がどのファイルに対応するか分かるように書く。
- 説明は変更の**意図**が主役。diff の逐語的な読み上げ (「この行をこう書き換えます」
  の羅列) はしない — それは diff 自体を見れば分かる。
- 自明な機械的変更 (typo 修正、ユーザが一字一句指定した変更、直前の説明の
  やり直し) は 1 行で足りる。省略はしない。
- 専門用語のレベル調整は `docs/claude/USER_LEVEL.md` と `annotate` スキルの
  基準に従う (説明文中の発展的用語には ※n 注釈を付けてよい)。

## 守るべきこと

- 説明は**ツール呼び出しの前**に置く。呼び出し後の「〜を変更しました」だけで
  済ませない (事後報告は変更理由の確認機会を奪う)。
- 事実のみ簡潔に。変更の正当化・自画自賛で膨らませない。
- 説明を書いたからといって、破壊的・不可逆な変更の事前確認義務が免除される
  わけではない (それは別のルール)。
