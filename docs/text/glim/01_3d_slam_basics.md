# 第1章 3D SLAM の基礎 — 2D で解けた問題が 3D で難しくなる理由

slam_toolbox で 2D SLAM を経験している前提で
([slam_toolbox 読本 第1章](../slam_toolbox/01_2d_slam_basics.md))、
3D になった瞬間に増える課題と、それを解くために GLIM が使う数学の道具
(factor graph・固定ラグ平滑化) をこの章で固める。

## 1.1 2D から 3D へ — 増えるのは次元だけではない

| | 2D (slam_toolbox) | 3D (GLIM) |
|---|---|---|
| 姿勢の自由度 | 3 (x, y, θ) | **6** (x, y, z, roll, pitch, yaw) |
| 地図の形 | 占有格子 | 点群 (+ボクセル統計) |
| マッチング | 相関 (窓内総当たり) | 反復最近傍系 (GICP/VGICP) — 総当たりは 6 次元では計算不能 |
| 絶対基準 | なし (全部相対) | **重力** (IMU が pitch/roll の絶対基準をくれる) |
| オドメトリ prior | 車輪 (直接使う) | GLIM は**使わない** (IMU のみ) |
| スキャンの歪み | ほぼ無視できる | **deskew 必須** (1 回転 0.1 s の間に機体が動く) |

3 つの新顔がそれぞれ章を持つ:

```
3D で新しく増える課題
├── ① 探索空間が 6 次元 ....... 総当たり不能 → 反復法 (ICP 系) + 良い初期値が必須 (第3章)
├── ② スキャン中に機体が動く ... 点ごとに撮影時刻が違う → deskew (第3章 3.4)
│   └── per-point time が必要 = タイムスタンプ読本 §4.5 の世界
└── ③ 重力という絶対基準 ...... IMU の加速度計が「下」を教える
    └── pitch/roll は絶対拘束できる。yaw と並進はできない (ここが事例A の伏線)
```

## 1.2 LO / LIO / CT-ICP — 3D オドメトリの系譜

3D SLAM のフロントエンド (LiDAR オドメトリ) には、IMU をどう使うかで流派がある:

```
3D LiDAR オドメトリの系譜
├── LO (LiDAR Odometry) ............ LiDAR 単独。LOAM (2014) 系
│   └── 初期値は等速仮定など。激しい動きに弱い
├── LIO (LiDAR-Inertial Odometry) .. LiDAR + IMU を密結合 ← GLIM の現行構成
│   ├── IMU が姿勢変化の高周波を担当 (100 Hz+)、LiDAR が低周波のずれ補正
│   ├── 重力で pitch/roll が絶対安定 + deskew の初期値も IMU から
│   └── 例: LIO-SAM, FAST-LIO, GLIM (odometry_estimation_cpu/gpu)
└── CT-ICP (Continuous-Time ICP) ... IMU レス。スキャン内の連続時間軌跡そのものを推定
    ├── 「スキャン開始時姿勢」と「終了時姿勢」を同時に解き、点を時刻で内挿して deskew
    ├── IMU 不要が利点。ただし等速仮定 + 重力基準なし
    └── GLIM の odometry_estimation_ct — reRoBot の旧構成 (IMU 入手前)
```

reRoBot は 2026-08-11 に CT-ICP → LIO へ切り替えた (BNO086 導入)。
両方式を同じデータで比較した実測が既にあり、結果は LIO の圧勝だった:
軌跡の総延長が車輪オドメトリ 48.5 m に対し **LIO 49.1 m (1% 差)** / **CT-ICP 307 m
(6 倍超 = フロントエンド破綻)**。CT-ICP は重力基準を持たないため pitch がドリフトし、
床が対角に傾いた (第 6 章 事例A の切り分け 3)。

## 1.3 factor graph — 拘束の帳簿

GLIM のバックエンドは slam_toolbox と同じく「グラフ最適化」だが、語彙が
**factor graph** に変わる。構造は同じものの一般化なので、対応で覚えるのが早い:

```
用語の対応
├── slam_toolbox: ノード (姿勢) + エッジ (相対姿勢拘束)
└── GLIM (GTSAM): 変数 (姿勢・速度・IMU バイアス) + ファクタ (任意の拘束)
    ├── 変数がロボット姿勢だけでなくなる (速度・バイアスも推定対象)
    └── 拘束も「相対姿勢」だけでなくなる (下記)
```

factor graph は「推定したい変数」と「変数間の観測拘束 (ファクタ)」の二部グラフで、
最適化は全ファクタの残差二乗和の最小化 — 考え方は slam_toolbox の Ceres と同じである。
GLIM が使うファクタの代表:

```
GLIM に登場するファクタ
├── マッチングコストファクタ (matching cost factor)
│   └── 「この点群とこの点群は VGICP 的に整合せよ」。エッジに誤差モデルごと埋め込む
├── IMU プリインテグレーションファクタ (第3章 3.3)
│   └── 「時刻 i→j の間、IMU 積分によれば姿勢・速度はこう変化したはず」
├── between ファクタ ......... 古典的な相対姿勢拘束 (create_between_factors で追加可)
└── 事前 (prior) ファクタ ..... 初期姿勢の固定など (init_pose_damping_scale が強度)
```

ライブラリは GTSAM (GLIM は 4.3a0 を要求 — reRoBot で glim が専用コンテナなのは、
これが LIO-SAM の要求する 4.2.0 や apt 版と衝突するため)。

## 1.4 固定ラグ平滑化 — 全部は解き直さない

グラフは走るほど育つ。全変数を毎回解き直すと計算が発散するので、GLIM のオドメトリ層は
**固定ラグ平滑化 (fixed-lag smoothing)** を使う:

```
時間軸 ──────────────────────────────────────▶
   [確定済み (marginalize 済み)] [直近 smoother_lag 秒の窓] now
    もう動かさない。要約だけ残す   ここだけ最適化し続ける
```

- 窓の長さがパラメータ `smoother_lag` (LIO: 5.0 s / CT: 1.0 s)。長いほど過去の観測で
  現在を補正できるが計算が重い
- 窓から出る変数は **marginalization** (周辺化) で「その変数が残りに与えていた影響の
  要約」に変換して捨てる — 情報は失わないが、もう修正はできない
- 増分最適化エンジンは **iSAM2**: 新しいファクタが来たとき、影響のある部分だけを
  再線形化して解き直す (`isam2_relinearize_thresh/skip` はその感度と頻度)

つまり GLIM の階層は「オドメトリ層 = 固定ラグの小さいグラフ」「グローバル層 = 全期間の
大きいグラフ」の二重帳簿になっている。この分業が第 2 章の 3 層構造の背骨である。

## 1.5 なぜ 2D は解けて 3D は流れたか (事例A の理論的な種明かし)

reRoBot の初評価 (2026-08-12) で起きたことは、この章の道具立てで説明がつく:

```
同じ廊下的環境・同じデータで
├── slam_toolbox (2D): 3 自由度 + 車輪 odom prior
│   └── 縮退する前進方向を車輪が直接拘束 → 解けた ✅
└── GLIM (LIO): 6 自由度 + IMU
    ├── pitch/roll: 重力で絶対拘束 → 床は水平 (傾き 0.1°) ✅
    ├── yaw・並進: LiDAR マッチング頼み
    │   └── 特徴の乏しい水平方向で縮退 → じわじわ流れる ⚠️ (壁が数 m の帯に)
    └── IMU の加速度二重積分は数秒でドリフト → 並進の prior としては弱い
```

IMU は「回転には強いが並進には弱い」センサである (加速度→速度→位置と 2 回積分する間に
バイアス誤差が二乗で効く)。車輪オドメトリが持っていた「前進方向の直接測定」は
IMU では代替できない — GLIM が標準で車輪オドメトリを**購読すらしない**
(subscribing topic に odom が無い) ことが、reRoBot の環境では効いた。
詳細な切り分けの実録は [第6章 事例A](06_case_studies.md)。

## 1.6 この章のまとめ

```
第1章 まとめ
├── 3D 化で増えるのは ①6 自由度 (総当たり不能) ②deskew ③重力基準
├── 系譜: LO → LIO (IMU 密結合) / CT-ICP (IMU レス・連続時間)
│   └── reRoBot 実測: LIO 49.1 m vs CT-ICP 307 m — 重力基準の有無は決定的
├── factor graph = 変数 (姿勢+速度+バイアス) × ファクタ (マッチング/IMU/between/prior)
├── 固定ラグ平滑化 = 直近 smoother_lag 秒だけ解き直す。外は marginalize (iSAM2)
└── IMU は回転に強く並進に弱い — 車輪 prior の不在は縮退環境で表面化する
```
