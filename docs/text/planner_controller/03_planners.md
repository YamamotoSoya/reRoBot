# 第3章 planner の地図 — 点で引くか、向き付きで引くか

planner は「どこを通るか」を決める部品である。アルゴリズムは多いが、本機の問題に効く区別は 1 つしかない。
**ロボットを点として扱うか、向きを持った形として扱うか**。
点として扱う planner は第2章の水色の帯だけを頼りにし、向き次第で当たる場所 (内接円と外接円の間) を区別できない。
向き付きで扱う planner はそこを区別できるが、どんな動きを許すか (旋回・後退) で性格が大きく変わる。

## 3.1 系統別の一覧

```
planner の系統
├── 格子探索 (点) ............... 格子のセルをつないで最短路を探す。向きを持たない
│   ├── Dijkstra / A*
│   ├── NavFn (Nav2) ............ Dijkstra/A* + 膨張コスト。ROS の古典
│   ├── Smac 2D (Nav2) .......... コストを考慮する A*
│   ├── Theta* (Nav2) ........... 格子に縛られない任意角度の直線で結ぶ
│   ├── D* Lite / Field D* ...... 障害物の変化に差分で再計画する
│   └── ARA* / AD* (SBPL) ....... 時間内に解を改善し続ける
├── 向き付き探索 (状態格子) ..... (x, y, θ) を状態にして、許された動きで探す
│   ├── Smac Hybrid-A* (Nav2) ... 車用。弧と直進 (Dubins / Reeds-Shepp)
│   ├── Smac State Lattice (Nav2) 動きの集合をファイルで与える。差動二輪用はその場旋回あり
│   └── SBPL Lattice ............ ROS 1 の State Lattice
├── サンプリング ................ 乱数で空間を探る
│   └── RRT / RRT* / RRT-Connect / PRM / Informed RRT* / BIT* (OMPL)
├── 最適化 ...................... 経路を最適化で曲げる
│   └── CHOMP / STOMP / TrajOpt
├── 構造化 ...................... 地図の形から経路の骨格を作る
│   ├── Voronoi (一般化ボロノイ図) .. 障害物から最も遠い線
│   ├── ポテンシャル場
│   └── 可視グラフ
└── 道路・グラフ ................ 事前に作った道の上を探す
    ├── Lanelet / Frenet (Autoware・Apollo)
    └── Nav2 Route Server (Kilted 以降)
```

本機 (差動二輪・前後非対称 0.65 × 0.84 m・狭路・人が動く・ノート PC) への適合度を付ける。

## 3.2 Nav2 公式の 5 つ

Nav2 の公式文書 (Setting Up Navigation Plugins、Tuning Guide) が挙げる planner は次の 5 つである。
「公式の対象」列は公式文書の表をそのまま訳した。

| プラグイン | アルゴリズム | 公式の対象ロボット | 車体の形の扱い | 経路の向き | その場旋回 | 後退 | 本機 |
|---|---|---|---|---|---|---|---|
| NavFn | Dijkstra / A\* (波面伝播) | 円形の差動二輪・全方向 | 円 (点 + 膨張) | なし | controller 任せ | なし | △ |
| Smac 2D | コスト考慮 A\* (8 近傍) | 円形の差動二輪・全方向 | 円 (点 + 膨張) | なし | controller 任せ | なし | △ |
| Theta\* | Lazy Theta\* (任意角度) | 円形の差動二輪・全方向 | 円 (点 + 膨張) | なし | controller 任せ | なし | △ |
| Smac Hybrid-A\* | Hybrid-A\* (Dubins / Reeds-Shepp) | 車型・脚型 (円形・非円形) | 任意形 | あり | なし | あり (Reeds-Shepp 時) | △ |
| Smac State Lattice | State Lattice (動き集合ファイル) | 非円形の差動二輪・全方向、任意 | 任意形 | あり | あり (差動用) | あり | ◎ |

公式の対象を読むと、本機の位置づけがはっきりする。
**非円形の差動二輪に公式が勧めているのは State Lattice だけ**である。
NavFn は「円形」が前提で、Hybrid-A\* は「車型」が前提であり、本機はどちらの前提も満たしていない。
reRoBot が 11-04 に Hybrid を選んだのは、差し替えが最も簡単で「向き付きの四角で衝突検査する」狙いを満たしたからだが、旋回の欠如がその後の主な制約になった (事例 C・D)。

公式文書は計画時間の目安も示している (約 75 m の経路): Hybrid-A\* 144 ms、State Lattice 113 ms、2D A\* 243 ms、NavFn 146 ms。
reRoBot の T480s での実測は Smac Hybrid で 0.02〜0.6 s (6〜52 m) だった。

## 3.3 点で引く planner — NavFn / Smac 2D / Theta\*

3 つとも、ロボットを点として格子の上で最短路を探す。
車体の知識は膨張コストだけで、水色 (253) を通行不可、勾配を「通れるが高い」として扱う。

```
点で引く planner の性質
├── 長所: 速い・単純・狭い所でも 1 セルの帯があれば線を引く
├── 短所 1: 向きを考えない。経路の各点の向きは空 (reRoBot の NavFn 経路は全点 yaw 0 だった)
├── 短所 2: 帯の外は全部「通れる」。四角が向き次第で当たる場所を区別できない
└── 帰結: 線は引けるが、その線を四角い車体で追えるかは controller 任せ
```

NavFn の出だしは「膨張の勾配を最短で下る」ので、障害物の近くから始めると横へ折れた線になりやすい。
これを弧で追う controller が後ろを振って止まったのが事例 A と B である。

Theta\* は線を斜めに伸ばして折れを減らすが、点で引く点は変わらない。

## 3.4 向き付き探索の考え方

向き付き探索は、状態を (x, y, θ) にして、**許された動き (motion primitive)** をつないで探す。

```
向き付き探索の 1 歩
├── 今の状態 (x, y, θ) から、許された動きを全部試す
├── 動きの終点の状態で車体 (四角) を置き、障害物に触れるか検査する
├── 触れなければ候補に加え、コスト (距離・曲がり・膨張コスト) を積む
└── ゴールに着くまで A* で繰り返す
```

「許された動き」が planner の性格を決める。

| planner | 許された動き |
|---|---|
| Smac Hybrid-A\* (DUBIN) | 直進・左の弧・右の弧 (半径は `minimum_turning_radius`) |
| Smac Hybrid-A\* (REEDS_SHEPP) | 上 + その後退版 |
| Smac State Lattice | ファイルで与えた任意の動き。差動二輪用の集合には「その場旋回」が入る |

## 3.5 Smac Hybrid-A\* — 車のための探索

Hybrid-A\* は自動運転車 (DARPA Urban Challenge) のために作られた方法で、車がその場で回れないことを前提にしている。
Nav2 の実装では、1 歩の弧を次の角度で作る (`nav2_smac_planner/src/node_hybrid.cpp:94`、Nav2 1.3.13)。

```
angle = 2 · asin( √2 / (2 · R) )     ← R は最小回転半径 (セル単位)
```

これは「弧の弦の長さが √2 セル (斜め 1 マス) になる角度」で、1 歩で必ず隣のセルへ移るように作られている。
この作りから、次の 3 つの性質が出る。

```
Hybrid-A* の性質
├── その場旋回が無い
│     移動量 0 の動きは同じセルに留まるので、この方式では表現できない
├── R と向きの刻みが縛り合う
│     1 歩の角度は向きの刻み (360° / angle_quantization_bins) の整数倍に丸められる
│     刻みが細かいほど、R が小さいと 1 歩が 1 セルに届かず、R が自動で引き上げられる (警告なし)
│     0.1 m 格子: 16 分割 → R ≥ 0.26 m / 32 分割 → 0.51 m / 64 分割 → 1.02 m
└── 仕上げの曲線も車用
      探索の最後に Dubins / Reeds-Shepp 曲線でゴールに直結し、内蔵の smoother で整える
      → 出てくる経路は R よりさらに緩い (reRoBot 実測: 最小半径 0.74〜1.6 m、中央値 1.09 m)
```

R を小さくしても経路は急にならない。11-05 の再生実験 (事例 E) では、R を 0.5 → 0.3 → 0.2 → 0.1 m と下げるほど狭路での成功が減った (向きの刻みが粗くなるため)。
差動二輪に Hybrid を使うと「どこでも弧でしか曲がらない」ロボットになる。

もう 1 つ、Hybrid (と Lattice) は**膨張半径が外接半径以上**であることを前提にしている。
満たさないと、起動時に ERROR を 1 行出したあと、全ての計画が 0.00 s で「no valid path found」になる (`nav2_smac_planner/src/collision_checker.cpp:54` 付近の `possible_collision_cost` の計算)。
reRoBot ではこれで最初の再生試験が全滅した (第7章のチェックリストに入れた)。

失敗の種類はログで区別できる (`nav2_smac_planner/src/smac_planner_hybrid.cpp:472, :476`)。

| ログ | 意味 |
|---|---|
| Start occupied | 始点の姿勢で既に当たっている。1 反復で終わった |
| no valid path found | 反復上限より前に探索が尽きた。通れる経路が無い |
| exceeded maximum iterations | 反復上限に達した。経路があるかは不明 |
| Goal ... outside bounds | ゴールが global costmap の窓の外 |

## 3.6 Smac State Lattice — 差動二輪のための探索

State Lattice は、動きの集合 (control set) をファイルで与える。
Nav2 には差動二輪用・全方向用・車用の生成ツールが付属している。

```
差動二輪用の動きの集合 (例)
├── 直進 (1 セル、2 セル …)
├── 左右の弧 (半径を複数)
├── その場旋回 (向きの刻み 1 つ分)  ← Hybrid に無いもの
└── 後退 (任意。有効にすると切り返しを含む経路が出る)
```

Hybrid と同じく向き付きの四角で衝突検査をするので、「点で引いて四角で詰む」問題は起きない。
そのうえで、狭い角では「止まって回ってから進む」経路を出せる。
これは NavFn + RPP 時代に controller 側で偶然実現していた動き (第4章 4.2.4) を、planner が衝突検査つきで正式に出すことに当たる。

導入に必要なのは、格子 (0.1 m)・向きの分割数・半径を決めて動きの集合ファイルを生成することと、planner の plugin 名とファイルの指定である。
planner が「回れ」という区間を controller が実行できるかは別問題で、RPP なら 45° 超の向きずれで旋回する機能、または Rotation Shim と組み合わせる (第4章)。

## 3.7 この章のまとめ

```
├── 本機に効く区別は「点で引くか、向き付きで引くか」
├── 点の planner (NavFn・Smac 2D・Theta*) は線を引けるが、四角で追えるかは保証しない
├── Hybrid-A* は車用。その場旋回が無く、R と刻みが縛り合い、経路は R より緩い
├── State Lattice は差動二輪の動き (その場旋回・後退) を衝突検査つきで扱える。公式も非円形差動に勧める
└── Smac は「膨張半径 ≥ 外接半径」でないと黙って全失敗する
```
