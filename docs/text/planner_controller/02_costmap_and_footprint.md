# 第2章 costmap と車体の形 — 「水色の帯」は何を意味するのか

RViz の costmap に出る紫・水色・赤〜青の帯は、色の好みではなくコスト値そのものである。
そして水色の帯の幅は、車体の形 (内接円) から決まっている。
この章では、コスト値の意味、膨張の仕組み、内接円と外接円、狭い道での余裕の収支を積み上げる。
第3章以降で planner と controller が「通れる・当たる」を判断するときの物差しはすべてここにある。

## 2.1 コスト値

costmap の 1 セルは 0〜255 の値を持つ。

```
コスト値 (Nav2 costmap_2d)
├── 254 LETHAL ............ 障害物そのもの (LiDAR の点・地図の壁・keepout)
├── 253 INSCRIBED ......... 障害物から内接半径以内。中心がここにあれば必ず当たる
├── 1〜252 ................ 膨張の勾配。障害物から離れるほど指数的に下がる
├── 0 FREE ................ 何もない
└── 255 NO_INFORMATION .... 未知 (reRoBot の global は track_unknown_space: false で使わない)
```

RViz の「costmap」配色ではこう見える。

| 値 | 色 |
|---|---|
| 254 | 紫 (マゼンタ) |
| 253 | 水色 (シアン) |
| 252 → 1 | 赤 → 紫 → 青 と薄れる |
| 0 | 無色 |

## 2.2 膨張 (inflation)

膨張層は、全ての 254 セルの周りに 253 と勾配を塗る。

```
1 つの lethal セルからの距離 d に対するコスト
├── d ≤ 内接半径 (0.325 m) ........ 253
├── 内接半径 < d ≤ inflation_radius ... 252 × exp(−cost_scaling_factor × (d − 内接半径))
└── d > inflation_radius ............ 0
```

reRoBot は `cost_scaling_factor` 3.0、`inflation_radius` は global 0.65 m / local 0.55 m。
膨張層は、**地図の壁も keepout も LiDAR の点も区別しない**。全ての lethal を同じ規則で膨らませる。
「地図由来だけ膨張を弱める」という設定は存在しない (やるなら地図の画像そのものを細らせる。第5章 5.4)。

## 2.3 内接円と外接円

本機の footprint は四角で、前後が非対称である。

```
footprint (base_link = 車軸中心から見た四隅)
  前 +0.325 ┌───────────┐
            │     ●     │  ← 車軸中心 (回転の中心)
            │           │
            │           │
  後 −0.51  └───────────┘
          左 +0.325   右 −0.325

内接円 = 中心から最も近い辺までの距離 = 0.325 m (左右の辺)
外接円 = 中心から最も遠い角までの距離 = √(0.51² + 0.325²) = 0.60 m (後ろの角)
          ※ Nav2 は footprint_padding 既定 0.01 m を足すので 0.62 m として扱う
```

この 2 つの円が、以後のすべての議論の物差しになる。

- **内接円の中に障害物があれば、どう向きを変えても必ず当たる**。内接円は車体の内側に完全に収まるからである。
- **外接円の外に障害物があれば、どう向きを変えても当たらない**。外接円は車体全体を包むからである。
- その間 (0.325〜0.62 m) は**向き次第**。四角の角を向けると当たり、辺を向けると当たらない。

## 2.4 水色の帯は「余白」ではなく「不可能」

水色 (253) は「障害物から内接半径以内」の帯である。

```
中心が水色の帯の中にある
 = 中心から 0.325 m 以内に障害物がある
 = 内接円が障害物に重なる
 = 車体をどう回しても障害物に触れる
```

したがって水色の帯は、保守的に足した安全マージンではない。**中心をそこに置くことが幾何学的に不可能な場所**の集合である。
帯を消しても通れる道は増えない。

では planner はなぜこの帯を使うのか。

```
帯の使い方
├── NavFn / Smac 2D ... 帯が車体について知っている唯一の情報。帯の外は全部「通れる」と見なす
│                       → 帯の外でも、向き次第で四角が当たる場所 (0.325〜0.62 m) を区別できない
└── Smac Hybrid / Lattice ... 帯の中は四角を置かずに即「当たり」と判定する (計算の近道)
                              帯の外の「向き次第」の領域だけ四角を置いて精査する
```

Smac が「`inflation_radius` を外接半径以上にせよ」と要求するのは (第3章 3.5、第7章)、
勾配の値から「この位置は外接円の内側に障害物があり得るか」を判定して、精査が要るかを決めているためである。
膨張が外接円より狭いと、この判定が成り立たない。

## 2.5 外接円が問題になる場面 — 旋回

後ろが長い車体は、回るときに後ろの角が大きな円を描く。

```
その場旋回 (車軸中心で回る)
├── 後ろの角が半径 0.60 m の円を描く → 直径 1.2 m の空きが要る
├── 前の角は半径 √(0.325² + 0.325²) = 0.46 m
└── 横 0.45 m に人が立っていると、その方向に後ろを振る旋回は不可
```

弧で曲がるときも同じで、曲がる側と反対の後ろの角が外へ振れる。
横の物体から縁で 0.11〜0.17 m しか離れていない状態で反対側へ急に曲がると、後ろの角がその物体を踏む。
これが事例 A (後端振り出し) の幾何である。

## 2.6 狭い道の余裕の収支

幅 0.8 m の道に幅 0.65 m の車体を通すと、余裕は両側 7.5 cm しかない。
この 7.5 cm は次の要因で簡単に消える。

```
余裕 7.5 cm × 2 を食うもの
├── 向き: 11° 傾けると占める幅 = 0.65·cos11° + 0.84·sin11° = 0.64 + 0.16 = 0.80 m (道幅いっぱい)
├── 格子: 0.1 m 格子では壁の隣のセル (0〜10 cm) を丸ごと壁扱い → 実質 2.5 cm
├── 自己位置: 地図の壁と実際の壁のずれ。reRoBot では約 0.15 m (事例 C)
└── 制御: controller の弧が経路の内側を切る分 (第4章 4.6、最大 8.5 cm)
```

向きの 11° は、Smac Hybrid の向きの刻み (32 分割で 11.25°) とほぼ同じである。
つまり「真っ直ぐの隣の向き」を取っただけで道幅いっぱいになる。
狭い道で planner が経路を出さないのは、この収支が負になるからである。

## 2.7 格子の量子化

costmap は格子なので、障害物の位置は格子の大きさで丸められる。

| 格子 | 量子化の最大誤差 | reRoBot で使う所 |
|---|---|---|
| 0.1 m | 10 cm | global (planner が見る) |
| 0.05 m | 5 cm | local (controller が見る) |

格子を細かくすると余裕を取り戻せるが、セル数は 2 乗で増える。
global を 0.05 m にすると 200 m 窓で 16M セルになり、窓を 60 m に戻す必要が出る (第5章 5.5)。

## 2.8 この章のまとめ

```
├── 水色 = 内接円が重なる = 必ず当たる。消しても道は増えない
├── 内接円 0.325 m と外接円 0.62 m の間は「向き次第」。ここを判断できるかが planner の差
├── 後ろが長い車体は、旋回で後ろの角が 0.6 m 振れる
└── 幅 0.8 m の道の余裕 7.5 cm は、向き 11°・格子・自己位置ずれのどれか 1 つで消える
```
