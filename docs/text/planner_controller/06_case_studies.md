# 第6章 事例集 — 実走と再生で何が起きたか

11-01〜11-05 の実走と bag 再生から 7 つの事例を解剖する。
各事例は **症状 → 機構 → 修正 → 教訓** の 4 部構成で、機構は第2〜4章の該当節を指す。
数値は bag の解析値で、解析の道具は `bags/tools/2026-11-02_person_stop/` と `bags/tools/2026-11-04_smac_run/` にある (⚠️ `bags/` は git 管理外)。
この期間の事例は docs/issue に個別の記録を作っておらず、一次資料は `docs/claude/PROJECT_STATE.md` の 11-01〜11-06 の記述である。

| 事例 | 一言 | 破った原則 | 状態 |
|---|---|---|---|
| [A](#事例a) | 横の物体の横で後ろを振る想定をして止まり続ける | 先読みが縮むと曲率が 4 倍 (第4章 4.2.2) | 解消 (先読み 0.6) |
| [B](#事例b) | 点で引いた細い帯に入り、出られない | 点の planner は外接円を知らない (第3章 3.3) | Smac で「入らない」に変わった |

## 事例A

**後端振り出しラッチ (11-01 bag `2026-11-01_2114_5goukan_chal_auto`、構成 NavFn + RPP 先読み下限 0.3)**

### 症状

776.8 s から 36 s、939.7 s から 38 s、横に物体がある場所で止まり続けた。RViz では機体が水色の帯に入って止まっているように見え、物体は機体に触れていなかった。解除はどちらもパッド操作 (812 s、977 s の `/joy_vel`)。物体が退いたのではない。

### 機構

```
├── 物体は左 0.45〜0.50 m、footprint の縁から 0.11〜0.17 m。現在姿勢の縁に lethal は無い (最大 253)
├── 経路は物体を避けて右に寄る。停止中は先読み 0.3 m で、先読み点の横ずれ 0.16〜0.19 m
├── 曲率 2y/L² ≈ 4 /m = 半径 0.24 m の急な右旋回を想定 (第4章 4.2.2)
├── その弧で footprint を掃引すると、後ろの左角 (−0.51, +0.33) が左へ振れて物体を踏む (第2章 2.5)
└── 止まると先読みが下限に張り付き、曲率も下がらない → 自己保持
```

再現: 記録された先読み点と local costmap で RPP の掃引を計算し直すと、4/4 時点で後ろの左角が当たる。先読みを 0.6 m にすると当たらない (0.45 m では当たる)。前端を実体の 0.14 m にしても結果は同じだった。

### 修正

`min_lookahead_dist` 0.3 → 0.6 (`6a911ec`)。検証は 2 通り。

| 検証 | 先読み 0.3 | 先読み 0.6 |
|---|---|---|
| controller_server を live にした bag 再生 (940〜958 s、350 指令) | 非 0 が 0 回、collision 360 回 | 非 0 が 257 回、collision 93 回 (物体の点の揺れ) |
| 閉ループ模擬 (costmap 固定) | 0 m | 2.5 m 抜ける (最小余裕 0.09 m) |

### 教訓

- 「水色の帯に入ると止まる」に見えても、止める判定は帯ではなく弧の掃引である。
- 先読み距離は停止距離と曲率の両方を決める。止まると下限に張り付くので、下限が停止中の振る舞いを決める。
- 副作用: 前方停止距離が 0.3 → 0.6 m に伸びた (第4章 4.2.3)。

## 事例B

**隙間進入 (11-03 bag `2026-11-03_2136_5goukan_chal_auto_min_lookahead_dist06`、NavFn + RPP 先読み 0.6)**

### 症状

止まり方が変わらなかった (10 区間、最長 30 s)。ユーザの体感は「機体幅の 2 倍くらいの隙間があるのに通れない」。

### 機構

165 s の local costmap:

```
├── 左 0.06 m に keepout の lethal、右 0.8 m に人。隙間は約 1.2 m
├── NavFn は隙間の中の「253 でない細い帯」(幅 0.15 m) に線を引く (第3章 3.3)
├── ロボットは keepout 側に寄った姿勢でその帯に入る
├── 先読み点の横ずれ 0.15〜0.49 m。45° を超える時刻はその場旋回モード (第4章 4.2.4)
└── 直進以外の全ての弧で、後ろの左側が keepout を踏む → 凍結。先読みの長さは関係ない
```

### 修正

先読み距離では直らない。原因は「点で計画して四角で追う」食い違いなので、planner を向き付きに替えた (事例 C へ)。
再生では Smac Hybrid はこの場面で経路を出さない (= 入らずに待つ)。

### 教訓

- 先読み 0.6 は「横ずれが小さく、片側だけに物体がある」場面の薬で、余裕がゼロに近い場面には効かない。
- 点の planner が引く「1 セルの帯」は、四角い車体にとって入口でしかない。

## 事例C

**Smac Hybrid 初実走の狭路 (11-04 bag `2026-11-04_1327_5goukan_chal_auto_SmacHybridA*`、30 分)**

### 症状

ユーザの体感: 至近距離や細い道ギリギリでも抜けるようになり、危険域を避けるための急旋回も減った。一方で、道幅がかなりないと通れない。ジグザグの区間は人の介入なしに通れなかった。

| | 11-01 NavFn (同じ区域) | 11-04 Smac Hybrid |
|---|---|---|
| 区域の通過時間 | 162 s | 301 s |
| 3 s 以上の停止 | 1 回 (waypoint の待ち) | 9 回 |
| collision ログ | 18 回 | 2069 回 |
| 計画失敗 | 1 回 | 62 回 (全体では no valid path 72・Start occupied 26・反復上限 2) |
| 縁から生け垣までの余裕の中央値 (global / local) | 0.29 / 0.43 m | 0.15 / 0.32 m |
| 経路の最小回転半径の中央値 | 0.34 m | 1.09 m |

### 機構

```
├── 生け垣の間の道幅は約 0.8 m。余裕は両側 7.5 cm (第2章 2.6)
├── 地図の生け垣は live より約 0.15 m 近い (global と local の余裕の差)。この量は 11-01 も同じ
│     → 自己位置が特別悪い日だったのではない
├── NavFn は点で 1 セルの帯を縫い、RPP は live (地図なし) で現実の 7.5 cm を見て通れた
├── Smac は四角が global (地図あり、0.1 m 格子) に経路全体で収まることを要求する
│     → 地図ずれ 0.15 m と格子 0.1 m で余裕が負になり「no valid path」
├── 出た経路は地図の中央 = 現実では片側に寄る → RPP が live で生け垣を検知して止まる
└── 経路の半径は 0.74 m 以上で、RPP のその場旋回も発動しない (第3章 3.5、第4章 4.2.4)
```

つまり、NavFn が通れたのは「楽観的な planner + 現実で守る controller」の組み合わせだったからで、Smac は地図を信じて厳密に判定するので、自己位置のずれがそのまま通行可否に跳ね返った。

### 修正

global の footprint だけ実寸より小さくした (幅 0.50 / 前 0.28 / 後 0.40、`e3d933f`)。controller は実寸のまま。
ジグザグの 5 時刻 (710 / 730 / 760 / 850 / 870 s) で planner を再生した結果:

| global footprint | global 格子 | R / 分割 | 経路が出た数 |
|---|---|---|---|
| 実寸 | 0.1 m | 0.5 / 32 | 0 / 5 |
| 実寸 | 0.1 m | 0.3 / 16 | 0 / 5 |
| 実寸 | 0.05 m (窓 60 m) | 0.3 / 32 | 2 / 5 |
| 楽観 | 0.1 m | 0.5 / 32 | 2 / 5 |
| 楽観 | 0.1 m | 0.3 / 16 | 2 / 5 |
| 楽観 | 0.05 m (窓 60 m) | 0.3 / 32 | 3 / 5 |

730 / 760 s はどの条件でも出なかった。直前の走行で生け垣に押し付けられた姿勢 (Start occupied) である。

同じ bag で、EPOS が 1064 s から指令に応答しなくなる事象も起きた (指令あり・車輪停止、CPU 停滞の署名なし、原因不明)。planner とは独立の別件として扱っている。

### 教訓

- planner を厳密にすると、自己位置のずれが「通れない」として表に出る。
- 楽観 footprint は「格子を半分にする」のとほぼ同じ効き目を持つ (0/5 → 2/5)。
- 狭路で向きを変えられない問題は残った (事例 D)。

## 事例D

**楽観 footprint で角を攻める (11-05 実走、ユーザ報告。bag は未解析)**

### 症状

地図のしきい値を上げて壁を細くした地図と、楽観 footprint で走った。
コーナーを攻めすぎて、LiDAR に写りにくい障害物にぶつかった。明らかに通れる場所でも、急旋回ができずに通ろうとしなかった。人の介入なしには通れなかった。

### 機構

```
├── 角の接触
│     ├── 楽観 footprint (7.5 cm) + 細い地図 → planner が角の内側を通る経路を出す
│     ├── 角の内側に、LiDAR に写りにくい物 (低い・細い) がある
│     └── global にも local にも載らない → 誰も止めない。楽観の代償がそのまま出た
└── 通れるのに通らない
      ├── Hybrid-A* はその場旋回を持たない (第3章 3.5)
      └── 向きを変えるには弧で回る空間が要る。止まって回る経路を planner が出せない
```

### 修正

11-06 に global footprint を実寸へ戻した (未コミット)。
旋回は planner の種類の問題なので、Smac State Lattice (その場旋回・後退あり) を検討中 (第5章 5.6)。

### 教訓

- controller が「実寸で守る」のは、センサに写る物に対してだけである。楽観の安全性は「死角に物が無い」ことを前提にしている。
- 「後退と旋回ができないと解決しない」はユーザの実走からの結論で、第3章の公式の対象表 (非円形の差動二輪 = Lattice) と一致する。

## 事例E

**効かなかった対策 (11-04〜11-05 の bag 再生)**

| 対策 | 狙い | 結果 | 効かなかった理由 |
|---|---|---|---|
| global `robot_radius` 0.45 | planner に大きい円を見せ、細い帯へ導かない | 全場面で No path | 自機が帯の中にいると NavFn は始点の周りが全部壁になる |
| ConstrainedSmoother | NavFn の経路の出だしを自機の向きに揃える | 横ずれ 0.16 → 0.13 m、強い重みでは悪化 (−46°) | 始点の向き固定は「元経路の最初の線分の向き」を固定する。NavFn の経路は全点 yaw 0 で、smoother は幾何から向きを付け直す |
| Smac の R を 0.3 / 0.2 / 0.1 m に | 小回りさせる | 狭路の成功 2/5 → 1/5 → 1/5 → 0/5、経路の半径は 0.74〜1.6 m のまま | 0.1 m 格子では R を下げると向きの刻みが粗くなる。仕上げの曲線が経路を丸める |
| local 格子 0.05 → 0.025 m | controller の量子化を減らす | 850 s は 0.05 でも通る、870 s は 0.025 でも止まる | 870 s は前の左角が live で既に lethal 上 (後退しか出口がない) |

教訓: 再生で「どの段の判定が止めているか」(planner の no valid path か、controller の collision か、現在姿勢の接触か) を先に切り分けてから対策を選ぶ。planner の再生は global しか読まないので、local の設定は controller の再生でしか評価できない。

## 事例F

**keepout の縁を這う経路 (10-15、`docs/issue/2026-10-15_keepout_corridor_stall_imu_yaw_jump.md`)**

### 症状

狭い通路で永久に止まった。

### 機構

keepout を costmap filter (KeepoutFilter) で入れていた。filter は膨張層の後に lethal を直接書くので、keepout の周りに 253 と勾配が付かない。
NavFn は keepout の縁から 3〜4 セルの所に線を引き、幅 0.65 m の footprint が縁に乗って RPP が止まった。

### 修正

keepout を StaticLayer として膨張層の前に積んだ (10-16、`nav2_params.yaml` の `keepout_static`)。壁と同じく 253 と勾配が付き、経路が通路の中央に寄る。

### 教訓

膨張されない障害物は、点の planner にとって「無いのと同じ」になる。costmap に何かを足すときは、膨張層より前か後かを確認する。

## 事例G

**自己検出点 (10-14 bag 1817、PROJECT_STATE の 10-14〜15 の記述)**

### 症状

自律走行が繰り返し止まった (停止 50 回のうち 37 回)。

### 機構

urg の右前 (−67°、0.33〜0.39 m) に、車体の一部を写した細い点が出ていた。footprint の縁のすぐ外にあり、RPP の現在姿勢の検査と前方の掃引に引っかかった。

### 修正と教訓

自己検出点の除去と footprint の実測 (10-15 に円 0.35 → 実寸の四角へ) を行った。
footprint の際に出る点は、物体か自分の車体かを最初に疑う。
