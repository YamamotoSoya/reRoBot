# 第1章 なぜ融合するのか — 単一センサの限界と相補性

この章は「そもそも車輪オドメトリだけでは何がだめなのか」に答える。
結論を先に言うと、**どのセンサも単独では嘘のつき方に癖があり、
癖の違う 2 つを混ぜると互いの嘘を打ち消せる**からである。
ただし「混ぜれば必ず良くなる」わけではないことも、この章の最後で予告する。

## 1.1 デッドレコニングの宿命 — 誤差は積分され、消えない

車輪オドメトリは**推測航法 (dead reckoning)** である。「今どこにいるか」を
外から観測するのではなく、「さっきの位置 + 今の移動量」を延々と足し込む:

```
x(t) = x(0) + Δx(1) + Δx(2) + Δx(3) + ...
                ↑ この Δ の 1 つ 1 つに誤差が乗る
```

足し算しかないので、**一度混入した誤差は永久に残り、蓄積し続ける**。
これがデッドレコニング系センサの宿命で、誤差の性質は 2 種類に分かれる:

```
デッドレコニングの誤差
├── 系統誤差 (systematic) ....... 常に同じ方向にずれる
│   ├── タイヤ径の較正ミス ...... 距離が定数倍でずれる (事例E: 実車が指令の 1/4 速)
│   ├── トレッド幅の較正ミス .... 旋回角が定数倍でずれる
│   └── 左右タイヤ径の差 ........ 直進しているつもりで円弧を描く
│       → 較正で潰せる。潰さない限り走行距離に比例して単調に成長
└── ランダム誤差 (random) ....... 毎回ランダムにずれる
    ├── 車輪の滑り (スリップ) ... 特に急加減速・旋回・段差で発生
    ├── エンコーダの量子化 ...... 1 パルス未満の動きは見えない
    └── 路面の凹凸 .............. 実効タイヤ径が揺らぐ
        → 較正では潰せない。√t で成長 (ランダムウォーク)
```

重要なのは、**車輪オドメトリの旋回 (yaw) 推定が特に弱い**ことである。
yaw は「左右の車輪の距離差 ÷ トレッド幅」で出す
(`ros2_ws_main/src/app/epos4_controller/src/epos4_odometry.cpp:141` の
`d_theta = (d_right - d_left) / tread_width_`)。距離そのものではなく
**2 つの距離の差**なので、両輪のわずかな滑りの差がそのまま角度誤差になる。
さらに yaw の誤差は位置誤差を**二次被害**として生む — 進行方向を 1° 間違えたまま
10 m 走ると、横方向に 10 × sin(1°) ≈ 17 cm ずれる。yaw 誤差は距離に掛け算で
効くため、位置誤差の中で最も高利貸しである。

## 1.2 車輪オドメトリと IMU の誤差特性 — 相補性

では IMU (ジャイロ + 加速度計) はどうか。両者の得意・不得意を並べる:

```
誤差特性の対比
├── 車輪オドメトリ
│   ├── ✅ 並進距離 ......... エンコーダ直読みで正確 (較正済みなら)
│   ├── ✅ 低速で安定 ....... 速度 0 なら距離も確実に 0 (ドリフトしない)
│   ├── ❌ yaw ............. 左右差の間接推定。滑りに弱い
│   └── ❌ 滑りを検出不能 ... 車輪が空転しても「進んだ」と報告する
└── IMU (BNO086)
    ├── ✅ yaw rate ......... ジャイロ直読み。車輪と独立、滑りの影響ゼロ
    ├── ✅ 高レート ......... 100 Hz (車輪 odom の同期レートより速い)
    ├── ❌ 並進 ............. 加速度の二重積分が必要で、バイアス誤差が
    │                         t² で爆発する。実用にならない
    └── ⚠️ 絶対 yaw ......... 磁力計基準。磁気外乱 (モータ・鉄骨) で汚れる
```

**互いの ❌ が相手の ✅ で埋まっている**。これが相補性であり、融合の根拠である:

- 並進は車輪から取る (IMU の二重積分は使わない)
- 回転は IMU から取る (車輪の左右差推定より直接的)
- 両方が同じ量 (yaw rate) を報告するときは、**それぞれの自信の度合いに応じて
  重み付き平均する** — この「自信の度合い」を数値化したものが第2章の共分散である

reRoBot の `ekf.yaml` はまさにこの分担をそのまま設定に落としている
(`ros2_ws_main/src/bringup/rerobot_bringup/config/ekf.yaml:6-14` の融合方針コメント。
解読は [第4章](04_robot_localization.md))。

## 1.3 融合は魔法ではない — 先に言っておく 3 つの限界

第6章の事例を先取りして、期待値を較正しておく:

1. **ゴミ入力はゴミ出力になる (garbage in, garbage out)**。
   融合器は入力メッセージの値も stamp も疑わない。`/odom` の twist が
   常時 0 なら、EKF は「速度 0」を信じて位置を進めない (事例A)。
   入力センサの較正 (事例E) は融合の前提であって、融合が肩代わりしてくれる
   ものではない。
2. **取付情報 (URDF) の間違いは観測の間違いになる**。IMU を裏返しに定義すると
   yaw が鏡像になり、EKF は鏡の世界を忠実に推定する (事例B)。
3. **質の悪い情報源を混ぜると悪化することがある**。reRoBot の実測では、
   360° 旋回の残差が生の車輪 odom で 0.1°、EKF 出力で +3.9° と、
   **融合した方が悪かった** (事例D、未解決)。磁北基準の yaw のように
   外乱で汚れる情報源は、混ぜる量 (共分散) か混ぜるか自体を考え直す必要がある。

つまり本書の主題は「EKF の使い方」ではなく、
**「EKF に何をどれくらい信じさせるかを、自分で決められるようになること」**である。

## 1.4 reRoBot が融合に踏み切った動機

一般論を離れて、本プロジェクトの文脈。2026 年 6 月の月次報告でユーザ自身が
課題をこう言語化している (`docs/monthly/2026_6`):

> 遅い、低速域での動作が安定しない、オドメトリ弱い。精度向上

`docs/claude/PROJECT_STATE.md` (§4 末尾) も同じ根を指している:
「SLAM が絶妙にずれる、低速でハンチング、Nav2 走行が遅い — いずれも
オドメトリ/エンコーダ問題が根っこ」。実際、エンコーダ較正 (事例E) で
系統誤差は潰したが、**yaw のランダム誤差は較正では潰せない** (§1.1)。
そこで 2026-08-11 に:

- BNO086 IMU を導入し (`/imu/data`)、
- `robot_localization` の EKF で車輪 odom と融合し、
- Nav2 の入力を `/odometry/filtered` に切り替えた
  (`ros2_ws_main/src/bringup/rerobot_bringup/config/nav2_params.yaml:97`)

という構成に移行した。同日の実機テストは一度失敗し (事例A/B/C の 3 連発)、
修正後の再テストで静止 305 秒のドリフト 14 mm / -1.1°、直進 10 m 誤差 0.8% という
結果を得ている (検証の詳細は [第7章](07_verification.md))。

## 1.5 この章のまとめ

```
第1章 まとめ
├── デッドレコニングの誤差は積分され、永久に残る
├── 系統誤差は較正で潰す (事例E)。ランダム誤差は較正で潰せない → 融合の出番
├── yaw 誤差は位置誤差に距離×掛け算で効く最悪の誤差 — そして車輪 odom は yaw が最も弱い
├── 車輪 (並進に強い) と IMU (回転に強い) は相補的
└── ただし融合は魔法ではない: 入力の較正・取付定義・情報源の質は自分で保証する
```
