# EKF センサ融合読本 — 車輪オドメトリと IMU を正しく混ぜる

2026-08-11 の初回実機テストで、EKF の出力 `/odometry/filtered` は
**ロボットが 20 m 走っても (0,0) から動かなかった**。EKF 自体のバグではない。
入力の `/odom` が「速度 0 のまま位置だけ進む」という矛盾したメッセージを
何ヶ月も前から publish し続けていて、位置しか見ない SLAM では無症状、
速度しか見ない EKF に繋いだ瞬間に発症した — センサ融合とはこういう世界である。
融合器は入力を疑わない。**入力の作り方・信じ方・検証の仕方**を体系的に知らないと、
「混ぜたら賢くなる」どころか、混ぜたことで初めて壊れる。本書はそれを
「なぜ融合するのか」から始めて、reRoBot で実際に起きた事故を教材に解説する。

## 読み方

- **初読は 1 → 2 → 3 章を順に**。融合の動機 (第1章)、不確かさという共通言語
  (第2章)、入力メッセージの作法 (第3章) の順で積み上がる。第4章以降は
  この 3 章を前提に書いてある。
- 「融合で何が壊れるのか」を先に見たければ **第6章の事例Aから**。
  必要な前提には各所で章リンクを張ってある。
- 第5章・第7章は reRoBot の開発中に繰り返し参照する実務ページ。
  EKF の調整・再検証のたびに第7章のプロトコルを回す。
- 時刻 (stamp・同期・queue) の話は姉妹書
  [ROS 2 タイムスタンプ読本](../timestamp/00_index.md) に委譲してある。
  本書は「値と不確かさ」、あちらは「時刻」が主役。
