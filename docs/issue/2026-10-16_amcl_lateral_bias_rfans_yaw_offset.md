# 10-16 AMCL の自己位置が建物に対して横 0.1〜0.5 m・yaw 数° 泳ぐ: 主因は R-Fans の方位ゼロが車体進行方向から ≈5.6° 回っていること

**ステータス: 解決 (原因特定 → URDF 反映 → 同日実走 0918 で確認: 横ずれ 0.38 → 0.14 m、バイアス −0.32 → +0.02、yaw 2.7 → 0.6°。§8)。**
反映: URDF 4 本の `rfans_joint` に +0.098 rad、`laser_joint` yaw −0.08727 → +0.0100 (urg も同じ分回す、ユーザ指示)、GLIM `T_lidar_imu` 4 JSON 再計算。
再測定ツール `tools/rfans_yaw_calib/` (設計 `docs/features/2026-10-16_rfans_yaw_calib.md`)。ツールの実測: 1643 で ε +5.90°±0.15 (n=98)、urg 相対角 −4.97° (n=157)。
対策 3 (積モデル) は `amcl.yaml` が別エージェント編集中のため未反映。
ユーザ観察「点群が建物に対して yaw / 横に 0.1〜0.5 m フラフラずれる」を 3 bag で数値化し、寄与を分解した。
主因 = **R-Fans の点群座標系の x 軸が車体の進行方向に対して約 5.6° 反時計回りに回っている** (URDF `rfans_joint` は yaw=0)。
AMCL は粒子をスキャンで決めた yaw (= LiDAR 軸) の方向へ odom 距離だけ進めるので、実機 (5.6° 時計回りに進む) に対し
更新ごとに左へ 0.275 × sin 5.6° ≈ 0.027 m ずれ、尤度の弱い引き戻しと釣り合って **左 0.3〜0.4 m + yaw 時計回り 1〜3°** に落ち着く。
スキャンを +0.098 rad 回して同じ bag で AMCL を再生すると横ずれ中央値 0.41 → 0.17 m、平均 −0.32 → −0.04 m (バイアス消失)。
従因 = `transform_tolerance 8.0` による 8 s 遅れ (横 +0.02〜0.09 m 中央値、p90 0.2〜0.3 m) と、nav2_amcl `likelihood_field` の
重み (1 + Σpz³、積でなく和) が平らで補正ゲインが低いこと (残る 0.17 m の揺れの土台)。ユーザ仮説の「地図解像度 0.1 m」は前提誤り
(照合地図は 0.05 m)、「植え込みの帯」は副次。

対象: `bags/raw/2026-10-15_{1752,1802,1709}_5goukan_chal_auto` (AMCL = `nav_amcl_scanall`、scan_all 2000 本、alpha 0.02、tol 8.0、

## 1. 測り方

- `wobble.py`: bag の `/tf` (実走 AMCL の map→odom、スタンプは受信 +7.85 s)、`/odometry/filtered`、`/rfans/scan_all`、地図 yaml を読み、
  各スキャン (1〜2 s 間隔) をセンサ姿勢に置いて、地図の距離場 (占有セルまでの距離、1 m でクリップ) の平均が最小になる微小補正
  (dx, dy, dyaw: 粗 ±1 m/±10° → 細 0.02 m/0.1°) を探索。補正を車体座標の 横 (lat、+ = 左) / 前後 / yaw に分解する。
  - seen = tf2 がスキャン時刻で返す map→odom (スタンプ補間 = 8 s 前の補正。RViz の LaserScan 表示・Nav2 の Time(0) と同じ)
  - lag0 = 受信時刻で最新の map→odom (tol≈0 相当)、lag2 = 2 s 前 (tol 2.0 相当)
  - 検証 `val1643/`: 地図を作った 1643 bag の GLIM 軌跡 (真値) に置いた残差 |lat| 中央値 0.02 m、yaw 0.2° (薄い地図 0.2-1.7 でも 0.04 m)
- `particles.py`: `/particle_cloud` 各粒子の当てはめ距離・広がり・AMCL 尤度 (cube-sum / product) の比。重みはリサンプル直後で一様 (neff=n) なので重み統計は使えない。
- `argmax.py`: AMCL の尤度モデル (Σpz³、σ_hit 0.2、z_hit/z_rand 0.5、2000 本) の argmax を AMCL 姿勢の周りで格子探索。
- `extra.py`: 車体座標の常在率 (随伴者)、IMU/scan の stamp−受信、時刻ずれ δ 走査。`urg_check.py`: urg を R-Fans 真値姿勢に置いた残差。
- `replay/replay_amcl.sh`: 同一 bag で AMCL 変種を再生 (ROS_DOMAIN_ID=151 で隔離、bag の map→odom は `tf_filter.py` で除去、
  `rot_relay.py` でスキャンを ε 回せる)。採点は `wobble.py --ref est.tum` → `refstat.py`。

## 3. 横バイアスの原因: R-Fans 方位ゼロ ε (critic が提示、独立に再計算)

直進 8 s 窓 (移動 >2 m、ヨー変化 <3°) で「移動方向 (弦) − LiDAR yaw の平均」:

| 軌跡 | chord − yaw | n |
|---|---|---|
| 1643 GLIM 軌跡 (`traj_lidar.txt`、AMCL も当てはめ器も無関係) | **−5.63° ± 0.34 (sd)** | 66 |
| 1752 当てはめ真値 / AMCL 姿勢そのもの | −5.44 / −3.21 | 5 / 4 |
| 1709 同上 | −6.09 / −2.12 | 11 / 6 |
| 1802 同上 | −4.17 (sd 3.9) / −1.89 | 11 / 8 |
| EKF odom (構造上 0) | −0.33 / 0.00 / −0.15 / −0.20 | — |

差動二輪は横滑りできないので、**車体は LiDAR 座標の x 軸から 5.6° 時計回りの方向へ進む** = R-Fans 点群の x 軸が進行方向の 5.6° 反時計回り側を向く
(駆動輪の向き・取付・ドライバの方位ゼロのどれかは未識別。URDF `rfans_joint` rpy=(0,0,0))。
AMCL 姿勢そのものの chord−yaw が −2〜−3° なのは、AMCL が yaw を時計回りに 2〜3° 外しつつ進行方向と LiDAR 軸の中間で妥協していることを示す。

符号の整合: 10-15 に「RViz で urg の壁が R-Fans の壁より反時計回りに約 5° ずれる」として urg を URDF で −5° 回した
(`laser_joint` yaw −0.08727、R-Fans 基準)。`urg_check.py` (urg を R-Fans 真値姿勢に置く) の残差は yaw −0.5° / 横 +0.04 m で両センサは一致。
つまり **urg は元々車体に合っていて、R-Fans の方が 5〜5.6° 時計回りに回っている** と読むのが整合的 (urg の −5° は R-Fans に合わせた分)。
→ 対策は `rfans_joint` yaw を +0.098 rad (≈ +5.6°) にし、`laser_joint` yaw を 0 に戻す (実機で廊下の角 2 面で要確認)。

機構 (critic): AMCL は粒子をスキャンで固定した yaw (LiDAR 軸) の方向に odom 距離だけ進める → 実機は ε だけ時計回りに進む → 更新 (0.275 m) ごとに
粒子は真値の左 0.027 m へずれる → 平らな尤度の弱い引き戻しと釣り合う所 (0.3〜0.4 m) に落ち着く。進行方向を向く (時計回りの) 粒子が生き残りやすい
ので yaw は時計回りに外れる。停止で凍結、旋回で一時リセット、直進で再成長 (1752 timeline T20→45 で −0.15→−0.9)。10-11 評価の
「2D 共通の横バイアス +0.5〜1.0 m、通路両端で時計回り −15〜−45°、3D (毎フレーム再収束) は 0」も同じ向き。

## 5. critic 査読 (2026-10-16) の要点

- 維持: 「遅れは従、AMCL 出力の誤差が主」「argmax = 幾何最良でモデル無偏」「解像度は前提誤り」「IMU 跳びは副次」。
- 弱めた: 「Σpz³ の平らさが機構」→ 平らさは対称なので向きを作れない。ゲインの低さの説明 (増幅器) であって原因ではない。
  「粒子広がり」は alpha との釣り合いで主従未分離。「薄い地図でもバイアス不変」は再当てはめの話で AMCL を薄い地図で回した証拠ではない。
- 棄却できず: 歩く随伴者 (H-B)。再生 relay で後左 0.5〜3 m を inf にする 1 本で分離できる (未実施)。
- 新本命 (H-A、本文 §3〜4 で因果実験まで実施): R-Fans 方位ゼロ ε ≈ 5.6°。
- 1802 の T240〜380 (廊下退化、2.97 m 跳び) は別事象 (10-15 issue §2) で統計から分けるべき。

  → keepout を StaticLayer で膨張させると 1 m 幅のスラロームは通路全体が inscribed になる (絵: `bags/exp/2026-10-16_loc_wobble/{0854,0918}/stall/`)。
