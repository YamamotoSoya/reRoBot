# 2D 自己位置推定 (AMCL / emcl2) が東端の角で見失う — 3D (lidar_localization_ros2) との bag 再生比較と全点スキャン追試

**ステータス: 調査中** — 現象は確定 (2 bag × 反復で再現)、原因は傍証どまり (critic 査読 3 回)。
効くレバーは「AMCL の運動ノイズ alpha1〜4 を 0.2 → 0.02」と「全点スキャン」の 2 つ、効かないものは「地図の高さ帯」「レーザ距離 100 m」「ビーム本数」。
3D は両 bag で xy 中央値 0.05〜0.07 m・見失い 0 で、実機の第一候補のまま。

対象: 地図 bag `2026-10-09_1643_5goukan_chal` (5 号館周回 1166 s)、評価 bag `2026-10-09_1611_5goukan_chal` (同コース別走行 1286 s、独立)。
ツール `tools/loc_eval/` (10-11 新設)、結果 `bags/exp/2026-10-11_loc_eval/` (以下 `$E`)、地図 `maps/2d/glim/2026-10-09_1643_5goukan_chal/` (以下 `$M`)。
関連: `docs/features/2026-10-10_lidar_localization_3d.md` (3D の設計)、`docs/issue/2026-10-01_amcl_hedge_corridor_scan_reduction.md` (植え込み通路の退化、前段)。

## 1. 背景と目的

- 10-10 に 3D 自己位置推定 (lidar_localization_ros2) を導入したが実データ未評価。2D は 10-01 の植え込み通路の退化 (別地図・別 bag) が未解決。
- ユーザ要望「2D と 3D を数値と絵で比較したい」→ 同じ bag・同じ基準で 3 方式を採点する評価系を作り、実機でどれを使うかを決める材料にする。
- 途中 (10-11) で「オフライン検証は中断して実機へ」→ 実機手順を整備 → 「再開して」で続行、10-12 にユーザ指摘 (帯の不一致、全点案) で追試。

## 2. 評価系と判断基準

### 2.1 仕組み

```
bag (1611 / 1643) ─ ros2 bag play (use_sim_time, /tf /tf_static /rfans/scan /rfans_driver/rfans_points /imu/data /odom)
   │                     qos_override.yaml で /rfans/scan を reliable に (emcl2 は reliable 購読、AMCL は best_effort 購読)
   ▼
loc_{amcl,emcl2,lidar3d}.launch.py (nav 構成の部品そのまま) ── TF map→odom
   │                                                           (3D は map→map_3d→odom の 2 段、z は橋が打ち消す)
   ▼
record_pose.py: /initialpose を odom 補正つきで送る (init_ok を記録) → TF map→base_link を 20 Hz で est.tum に記録
              + /amcl_pose の共分散 (cov.txt)、TF の遅れ (latency.txt)、再生ログ (replay.log)
   ▼
score.py: 基準軌跡と時刻合わせして xy / yaw 誤差 → summary.md / results.json。plot.py で地図上の軌跡・時系列・CDF
```

- **基準軌跡** (`ref_1611_fit`, `ref_1643_fit`): GLIM の軌跡 (1643 は地図元なのでそのまま、1611 は別走行なので 2D 地図同士を ICP で剛体登録してから) をスキャン当てはめで精密化。
  critic が再計算して基準のヨーは GLIM と ≤0.3°、3D 推定が基準に対し全区間 |0.1| m 以内 = 基準は横方向に正しい。
- **初期姿勢**: 全 run 同じ (`initialpose.yaml`)。AMCL は尤度場構築中 (≈13 s) に /initialpose を受けると bond が切れて再起動する → `bond_timeout` 60 s + 再送で回避 (§9)。
- **1 本ずつ直列**: 同じ DDS domain で 2 本同時に再生しない。再生中は解析も走らせない (10-12 r1 で TF 遅れ 0.4〜0.8 s を作った、§9)。

### 2.2 指標と判断基準

| 指標 | 定義 | 判断基準 |
|---|---|---|
| xy 中央値 / p95 / 最大 | 基準との平面距離 (initialpose 以降) | 3D 0.07 m が物差し。0.5 m 台 = 2D として良、1 m 超 = 悪 |
| 見失い | xy 誤差 >1 m の区間 (回数と合計秒) | 「復帰しない見失い」(以後ずっと >5 m) があれば運用不可 |
| 5 m 超に落ちる位置・時刻 | `lost_at` (est を 5 本おきに見て >5 m の出入り) | 場所が固定か乱数かで、幾何由来か推定器由来かを分ける |
| 区間平均 (0-200 / 200-300 / 300-400 / 400-600 / 600-900 / 900-1300 s) | `seg.py` | 300〜400 s = 角手前、400〜600 s = 東端の角〜南通路入口、600〜900 s = 南通路 |
| 誤差の分解 along / across / yaw | 基準姿勢の前後 (前+) / 左右 (左+) / ヨー [deg] (`err_decomp.py`) | 「ヨーが先か、along が溜まるか」で機構を絞る |
| 粒子分布 sqrt(cov_xx+cov_yy) | /amcl_pose の共分散 (cov.txt) の 100 s 中央値 | <1 m = 一山に収束、>10 m = 二山以上に割れている (崩れる予兆) |
| TF 遅れ | TF の stamp と受信時刻の差 (latency.txt) | 正常 0.044 s。0.5 s 以上が続く run は CPU 過負荷で評価不能とする |
| 静的尤度 (`fit_landscape.py --model amcl`) | 基準姿勢を前後 ±1/2/5 m・左右 ±0.5/1/2 m・ヨー ±5/10/20° に振った AMCL 尤度の比 | 基準が最大なら地図は正しい。通路で ±12° の残存率が高い = 尤度が鈍い |
| 反復 | 同条件 2〜3 本 (AMCL の種は time(NULL) 秒単位なので 22 分離せば独立) | 1 本の結果は「傍証」、同時刻・同場所で揃えば「確定」 |

critic (反証 subagent) を原因の表現を決める前に 3 回起こした (10-11 全体評価、10-12 alpha / 帯、10-12 全点)。以下の「確定 / 傍証 / 棄却」は査読後の表現。

## 3. 何が起こったか (第 1 ラウンド、現設定)

条件: 地図 `raw_traj/0.2-1.7` (GLIM 軌跡 + 点群、帯 0.2〜1.7 m、range 30 m、0.05 m/px)、スキャン = bag の `/rfans/scan` (bringup 既定: 帯 0.3〜6.0・0.2° 刻み 1796 席・range_max 150、扇内最近点)、AMCL `amcl.yaml` (likelihood_field、max_beams 60、laser_max_range 30、alpha1〜4 0.2、recovery_alpha 0)、emcl2 `emcl2.yaml`、3D `lidar_localization.yaml` (ndt 2.0 / 5.0)。

| 構成 | 地図の作り方 | 1611 xy 中央値 | 1611 見失い | 1643 xy 中央値 | 1643 見失い | 5 m 超に落ちる位置 |
|---|---|---|---|---|---|---|
| 3D ndt 2.0 (全地図、scan voxel 0.3) | glim_pcd | **0.07 m** | 0 | **0.05 m** | 0 | — |
| 3D ndt 5.0 | glim_pcd | 0.10 m | 2 回 7 s | 0.10 m | 6 回 22 s | x≈105〜125, y≈−58 (南通路、両 bag 同じ場所) |
| AMCL traj 0.2-1.7 ×3 | traj | 70 m | 377〜383 s 以降復帰なし | 40 m | 411 s 以降 | x≈150〜157, y −26〜−30 (東端の角) |

崩れ方 (12 run 共通、`err_decomp.py`):
1. 直線通路の両端 (x≈99〜106 の植え込みの切れ目 + 動体、x≈139〜150 の角手前) で推定が**時計回り −15〜−45°・後ろ・右**へ同符号でずれる。通路内部 (x 110〜135) は小さい。
2. 角直前の 30 s 停止で誤差が凍結したまま。
3. 東端は占有率 60〜78% で尤度場が飽和 (ヨー ±12° 振っても当たり率 0.91〜0.95) → そこで発散し、`recovery_alpha 0` なので戻らない。
4. 健全性 (critic 再計算): EKF の odom→base_link は回頭ずれ ≤0.9〜1.3°/区間・距離 +2.5%、スキャン 8.6〜9.2 Hz 欠落なし、乱数種の違う 3 本が同時刻 ±5 s に同方向へ外れる = 入力に決定論的に従っている。再生機構 (遅れ・QoS) は時刻と無相関。

## 7. 判定 (critic 査読後)

**確定**
- 2D (現設定・近点スキャン) は bag によらず東端の角で見失い復帰しない。基準・odom・再生機構は健全。
- 3D ndt 2.0 は両 bag で 0.05〜0.07 m・見失い 0 (CPU・TF 鮮度・初期姿勢誤差耐性は実機未評価)。
- 地図の高さ帯 (H4)、レーザ距離 100 m (H5)、随伴者の帯 (H3) は角の見失いの原因ではない (それぞれ変えても 10/10、1/1、1/1 で同じ場所で脱落)。
- 既定 alpha (0.2) は全点でも運用不可 (南通路で粒子が二山に割れ、4/4 がどこかで飛ぶ。崩れる位置は乱数)。
- AMCL の CPU 負荷は実ビーム数 × 粒子数に比例。近点 1795 本は破綻、全点 2000 本 (実 ≈750) は 1 コア 100% で TF 遅れ 0.044 s を保てた。

**支持 (傍証つき)**
- alpha 0.02 が主レバー: 全構成 0.51〜0.63 m、粒子分布 <1.1 m。ヨーずれそのものは残る。
- 全点スキャンにすると既定 alpha でも角を通過する (4/4 vs 近点 0/10、Fisher 正確確率 ≈0.005)。本数 (実 750 でも 22 でも) にも帯 (0.3〜100 でも 0.3〜6.0 でも) にもよらない → 残る候補は**選点法** (近点 = 0.2° 扇内の最近点 → 植え込み・随伴者など近接クラッタ優先、全点 = 0.009° ビン単点 → リング上の点をほぼ均等に拾う)、または再生成スキャン固有の何か (cadence 7 Hz 等)。**未分離**。
- 全点 + alpha 0.02 が 2D 最良 (0.51〜0.54 m、最大 1.5〜2.3 m、n=4)。近点 60 本との差は角手前のヨーと最大値だけで、中央値の差 (0.52 vs 0.60) は小さい。

**ユーザ仮説「帯 0.3〜100 × 100 m × 全点が最も情報量が多く縮退しにくい」への答え**
効いたのは「全点」で、「帯 0.3〜100 の高所・遠点」と「100 m」は同条件の 0.3〜6.0 全点・30 m と差が出なかった。縮退 (南通路の粒子拡散) は既定 alpha では全構成に残り、alpha 0.02 でだけ消える。2D 最良 0.51〜0.54 m は 3D の 7 倍で、その差の大半は 2D 共通の横バイアス (未解明)。

**棄却**: H3 随伴者の帯、H4 帯不一致、H5 遠点不足。**未検証**: H2 (地図を変えた再生)、H7、emcl2 の全点 (n=1・alpha=0 退化設定のまま)。

## 8. 残る問いと次の実験 (安い順)

1. 選点法の分離: scan_all から 0.2° 扇ごとに最近点を選び直したスキャン (近点と同じ選点法、全点と同じ帯・cadence) を alpha 0.02 と既定 alpha で 1 本ずつ → 角を越えなければ選点法、越えれば再生成固有。
2. 既定 alpha の全点をあと 2〜3 本 (南通路で崩れる位置の乱数幅)。
3. 横バイアス +0.5〜1.0 m の由来: 粒子平均の偏りか地図投影か (a002 の est と /amcl_pose の粒子統計を区間別に)。
4. alpha 0.02 / 全点を 1643 でも (bag 依存でないことの確認)。
5. emcl2 を alpha が 0 にならない設定で (帯を消した地図 + range_threshold) 1 本。
6. 実機: `nav_amcl_scanall` (bringup `rfans_scan_all:=true`) + alpha 0.02 + max_beams 300〜500 vs `nav_lidar3d` を同じコースで (CPU・TF 鮮度・EPOS RPDO 途絶との兼ね合い)。

## 9. 落とし穴 (再現する人向け)

- AMCL は最初のスキャンで尤度場を作る間 (0.05 m 地図で ≈13 s) に /initialpose を受けると bond 心拍が止まり、manager が再起動して初期姿勢が消える → `loc_amcl.launch.py` で `bond_timeout: 60.0`。実機で RViz の 2D Pose Estimate を早く送っても同じことが起きる。
- emcl2 は /rfans/scan を reliable で購読する。bag の記録は best_effort なので `qos_override.yaml` で reliable に。pointcloud_to_laserscan の出力も best_effort → `scan_relay.py` で中継。
- `ros2 run` を `kill $!` してもノード本体が残る。`pkill -f rfans_to_scan_all` で止めないと次の run で publisher が 2 本になる。
- 再生中に解析スクリプトや `ros2 topic hz` (39,270 席のスキャンを Python で受ける) を走らせると AMCL の TF 遅れが 0.4〜0.8 s になり更新回数が 15% 減る (R5 r1)。再生は 1 本ずつ、解析は終わってから。
- dump 由来の 2D 地図は地面のまだら占有で尤度場が平ら (4 m ずれても当たり率 95%)。AMCL には traj 版を使う。
- 2D 地図同士の ICP 登録は yaw に盲目になりうる (評価値を 2 m 打ち切り平均に変更済み)。基準が 1〜2 m 滑らかに振れたら登録の yaw を疑う。
- AMCL の乱数種は time(NULL) 秒単位。並走コピーは非独立、直列の反復 (22 分離れる) は独立。
- 地図 `_r100` は 10432×7104 px (74 MB)。尤度場構築が長いので `bond_timeout` を戻さない。
