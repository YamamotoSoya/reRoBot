# 停止時に scan が左右に揺れる — 真因はゲームパッド電池切れ (stamp=0 は別件の潜在欠陥として記録)

- **ステータス: 解決 (真因判明: ゲームパッドの充電不足)。ただし §機構 の stamp=0 は実測事実であり、潜在欠陥として残存**
- 発覚: 2026-08-01 (slam_toolbox マッピング中)
- 関連: `docs/report/` 2026-07-31 スルーレートリミッタ導入、
  `docs/issue/2026-07-07_wheel_odometry_encoder_scaling_4x.md`

## 結論 (2026-08-01 更新)

停止時の左右ブレの真因は**無線ゲームパッドの電池切れかけ**。瀕死のパッドは入力を
「全開⇄ゼロの高速フリッカー」(実測: /robot_speed_cmd が毎秒 ~19 回反転、angular にも
±2.0 rad/s が混入) として取りこぼす。スティック解放の瞬間に旋回指令が 0⇄±全開で
数百 ms 暴れ、機体が実際に微小な首振りをしていた (旋回指令は左右輪を逆回転させる
ため「タイヤが左右交互に止まる」見え方とも一致)。

反証実験: 下記「窓ズレ + 起動くじ引き」仮説は、パッド充電後に**10 回再起動して
一度も再現しない**ことで棄却された (起動位相依存なら 10 回中数回は出るはず)。
再起動で治ったように見えたのは、無線パッドの電池が休止で一時回復していたため。

教訓: 電池切れかけのパッドは「入力が消える」のではなく「全開とゼロを高速往復する」
形で壊れる。deadman (LB) を握っている間はその暴れがそのまま通る。屋外走行前の
パッド充電確認をチェックリストに入れること。

---
以下は当初の (棄却された) 仮説の記録。ただし手順 1 の stamp=0 実測は事実で、
epos4_odometry の同期設計上の潜在欠陥として今後も有効な情報。

## 症状

- 減速停止の間 (~0.4 s)、RViz 上で scan が世界座標に対して左右に振れる。
  タイヤ表示も左右交互に止まって見える。実機は滑らかに停止。
- 等速走行・等速旋回中は scan は世界に固定されて見える (定常項は健全)。
- 停止後の最終姿勢は正しい (ゼロ平均の過渡ノイズ)。
- **再起動すると出たり出なかったりする** (2026-08-01 に再起動で消失を確認)。

## 機構

1. **ros2_canopen Cia402Driver の joint_states は header.stamp が常に 0** (実測:
   両モータ 40 msg 全て sec=0, nanosec=0)。
2. `epos4_odometry` の ApproximateTime 同期はスタンプが全メッセージ同値 (0) のため
   時刻照合として機能せず、**実質「到着順ペアリング」に退化**している。
   `setMaxIntervalDuration(50ms)` も無効 (差は常に 0)。
3. 左右ドライバの実際のサンプリング位相 (PDO 周期 50 ms 内のどこか) は
   **起動タイミングで毎回決まる**。さらにどちらか片方のメッセージが 1 個落ちると
   到着順ペアリングは以後 **恒久的に 1 周期 (50 ms) ずれたペア**を作り続ける。
4. ペアの左右が Δt ずれた時間窓の移動量になると、偽の旋回
   `d_theta ≈ (減速度 × Δt × 周期) / tread` が発生する。
   等速中はゼロ、速度変化中のみ現れる — 観察と一致。
   例: 減速 3.1 m/s² (ランプ 2000 rpm/s)・Δt 25 ms・周期 50 ms → 1 更新あたり ~0.5°。
5. odometry の TF スタンプは stamp==0 フォールバックで `now()` になっている
   (`epos4_odometry.cpp:98-100`) ため TF 自体は流れる — 症状が姿勢ノイズだけに
   とどまる理由。

## なぜ今まで顕在化しなかったか

- 2026-07-31 のスルーレートリミッタで減速が ~0.4 s の一定減速区間に引き延ばされ、
  単発キックだった偽ヨーが 8 回連続の振動として知覚されるようになった。
- 2026-07-29 のエンコーダ修正で実車速度が 4 倍になり、減速度も比例して増えた
  (偽ヨー振幅は減速度に比例)。
- 症状の有無が起動ごとのくじ引き (位相 + メッセージ落ち) なので再現が不安定。

## 修正案 (未実装)

`epos4_odometry` からスタンプ依存を除去する:
- ApproximateTime をやめ、左右を独立購読して**到着時刻 (`now()`) を自前で記録**、
- 固定周期タイマで両輪の位置を「共通時刻」へ線形補間してから差分を取る。
- これで窓ズレ項が消え、メッセージ落ちでもペアが恒久シフトしない。

代替/上流対応: ros2_canopen 側で joint_states に正しい stamp を入れる
(ドライバ改修が必要。apt 配布物なら手を入れにくい)。

## 検証手順 (症状再発時)

1. 走行→停止しながら両モータ生 topic と /odom を記録し、
   各ストリーム単体の位置変化は滑らか・/odom yaw のみ振動、を確認する。
2. `max_motor_decel_rpm_per_s` を半分にすると振幅半減・継続時間倍増する
   (窓ズレ理論の定量予言)。
