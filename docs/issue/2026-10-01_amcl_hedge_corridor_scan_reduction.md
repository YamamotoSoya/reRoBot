# AMCL が植え込み通路で見失う — スキャン変換の「選び方」を変えた並走比較

**ステータス: 調査中** (選び方の効果は未検出。通路の進行方向退化は総当たり照合で直接確認、critic 査読は (1)〜(3) のみ・総当たり結果は未査読)

対象 bag: `bags/raw/2026-09-27_1948_5goukan_auto` (5 号館 Nav2 自律走行、地図 `maps/2d/glim/2026-09-180915_dumpbase`)。
見失い: bag 先頭から 229〜268 s の植え込み通路 (x≈8→20 m) で σ が膨らみ 268 s に 12 m 飛ぶ。651 s にも 31 m。
前段の解析 (09-28): 通路の /scan 終点の 7〜8 割が 2 m 先の植え込み (高さ 0.3〜0.7 m) に吸われ、平行 2 線だけになって進行方向が退化する (メモ amcl-hedge-corridor-degeneracy)。

## 1. 何を試したか

3D→LaserScan の方位ビン (0.2°) に入る複数リングの点から **どれを代表にするか** を変え、同じ bag 入力で AMCL を名前空間付きで並走させた (TF なし、`/initialpose` は共通)。

| 変種 | スキャン | AMCL |
|---|---|---|
| base | 記録済み /scan (pointcloud_to_laserscan、ビン内**最近点**) | 現行 (max_beams 60) |
| far | 自作 `rfans_scan_modes` mode=farthest (ビン内**最遠点**) | 同 |
| nth1 | 同 mode=nth k=1 (**2 番目に近い点**) | 同 |
| all | pointcloud_to_laserscan の angle_increment を R-Fans 方位刻み 0.00016 rad に (**ほぼ全点**が自分の席を持つ) | max_beams 2000 |

ツール: `tools/amcl_compare/` (README 参照)、`ros2_ws_main/src/app/rfans_scan_modes`、`rerobot_bringup/launch/amcl_variants.launch.py`。
結果: `bags/exp/amcl_variants/` (`1948_A` 単発、`1948_R4`・`1948_C2〜4` 種非独立の反復、`1948_S1〜4` 種を分けた反復)。

## 2. 分かったこと

### 2.1 確認できた事実

- **再生は live の入力を再現している**: 見失い直前まで live と再生 base の位置は 0.1 m 以内、AMCL 更新回数も一致 (200〜268 s: 65 vs 66)。live の rosout に AMCL のスキャン破棄警告はない。
- **同じ入力でも見失う/見失わないが分かれる**: 単発再生の base は見失わず、R4 では 4 コピー中 3 つが見失った。結果は起動条件 (乱数種・最初に受理されるスキャン = 更新位相) に強く依存する。
  - nav2_amcl の粒子フィルタは `srand48(time(NULL))` (秒単位) で種を決めるので、同じ秒に configure されたコピーは同じ乱数列になる。R4/C2〜4 の「16 run」は独立でなく、実効サンプルは 8〜11 (critic 指摘)。
  - 種を 2 s ずつずらし、bag を全コピー活性化後に流した S1〜4 (各変種 24 コピー) でも、互いに異なる軌跡は変種あたり 8〜13 本しかなかった。乱数種だけでは結果は分かれず、更新位相が揃うと収束する。ばらつきの主因は**更新位相 (起動タイミング)** の可能性が高い (未検証)。
- **通路の進行方向の退化を直接確認 (291 s の静止区間)**: スキャン 10 本を地図に総当たり照合 (x, y ±2 m / 5 cm、yaw ±10° / 0.5°、AMCL と同じ尤度場)。

  | 姿勢 | 尤度スコア | 最良からの距離 |
  |---|---|---|
  | 最良 (20.48, −1.58, 0.6°) | 0.87 | — |
  | AMCL (見失わなかった run の中央) | 0.74 | 0.13 m |
  | operator の initialpose (19.28, −1.98, −5.4°) | 0.29 | 1.27 m |

  スコア 95% 領域は通路方向 (174°) に σ 0.41 m、横方向 0.04 m で **10:1 に細長い**。最初に「全変種に共通の ~1 m ずれ = AMCL の偏り」とした解釈は誤りで、**ずれていたのは operator のクリック**だった。見失わなかった AMCL は正しい。

### 2.2 選び方の効果 (未検出)

S1〜4、291 s の参照点 = 総当たり最良姿勢ではなく operator 姿勢で集計 (大誤差 > 5 m):

| 変種 | 独立 run | 大誤差 run | 平常 run の operator からのずれ (dx, dy) |
|---|---|---|---|
| base | 11 | 0 | +1.07, +0.39 (= 最良姿勢とほぼ一致) |
| nth1 | 13 | 0 | +1.16, +0.38 (同上) |
| all | 12 | 4 | +0.97, +0.40 (同上) |
| far | 8 | 0 | +0.54, +1.59 (**最良姿勢から約 1.2 m 横にずれる**、yaw 6.7°) |

- 種非独立の R4/C2〜4 では base が見失い、S1〜4 では base は見失わず all が 4/12 見失った。**どちらの集計でも変種間の差は統計的に有意でない** (Fisher 片側 p ≥ 0.26)。起動条件の違いで順位が入れ替わる程度の差しかない。
- **far は平常時の位置が悪い** (最良姿勢から約 1.2 m、yaw 約 6°)。手前の植え込みを捨てて奥の点を選ぶと、地図 (植え込みも壁として描かれている) と合わなくなるため。大ジャンプが 0 でも採用候補にならない。
- nth1・all は base と区別がつかない。

### 2.3 棄却できていない代替仮説 (critic 査読より)

- live の見失いは起動条件の不運ではなく、live 固有の負荷・タイミング差 (Nav2 + RViz + 録画、190 s より前から稼働していた粒子状態) によるもの。再生のジャンプが live と同じ時刻・地点 (268 s、x≈20) に集まるかを未確認。
- all の C3 同時失敗は、共通入力 (pointcloud_to_laserscan 39k ビンの負荷による点群欠落) によるもの。C3 と C4 の `/scan_all` 件数・stamp 間隔を未比較。
- 採点地図 (bag の /map) と再生で使った地図ファイルの一致は未確認 (同サイズ・同 origin までは確認済み)。

## 3. 次の手

1. **更新位相をランダム化した反復**: 再生ごとに `--start-offset` を 0.0〜1.0 s ずらし (位相が変わる)、種も分ける。変種あたり 30 run 以上で失敗率を比べる。現状の n では 5/16 vs 0/16 程度の差しか検出できない。
2. 選び方より効きそうな軸に移る: **帯の変更** (下限を植え込みより上の 0.7〜0.8 m に、地図も同じ帯で作り直す。09-28 の帯テストで進行方向幅 1.75 → 0.75 m に改善の兆し) と **AMCL パラメータ** (`laser_likelihood_max_dist`、`max_beams`、`recovery_alpha_slow/fast` の再散布)。`amcl_variants.yaml` に 1 行足せば同じ枠組みで比較できる。
3. 総当たり照合 (`brute_force_pose.py`) を他の静止点 (505/545/692 s の operator 再設定) にも当て、真値の代わりに使う。
