# GLIM 屋外地図の「床が坂になる・柱が地面を突き抜ける」— 要点版

元ファイル: [`2026-09-10_glim_z_drift_not_vangle.md`](2026-09-10_glim_z_drift_not_vangle.md) (調査ログ。§番号は元ファイルのもの)
最終更新: 2026-09-24 (critic 査読済みの結論のみ載せる。§15 生 IMU ドリフト計測まで反映)

## 1. 一言でいうと

平らな道を走っているのに、GLIM は **位置の z だけがエスカレーターのように上がったり下がったりする**。原因は IMU でも地形でも LiDAR の縦角表でもなく、**LiDAR 点群の照合 (GICP) が上下方向に滑る**こと。滑る向きは進行方向で決まり、往路で上り・復路で下るので 1 周すると帳消しになる。そのため始点と終点は合うのに途中が山になり、同じ柱が別々の高さに描かれて地面を突き抜ける。

## 2. 見えている症状

|---|---|---|

## 3. 原因の全体図

```
床が坂になる・柱が地面を突き抜ける
├── A. 進行方向で決まる z の滑り (heading 依存傾き)                【本命〜確定寄り — 09-10〜09-20 の 40 run 超】
│    ├── 何が滑るか: 主に位置の z。車体姿勢は 1° 以内 (IMU・生点群・GLIM 姿勢の 3 証拠、§11.2。ただし GLIM 姿勢は IMU に逆らって 1.4° 傾く、§14.5)
│    ├── どこで滑るか: 照合 (GICP) の段。植栽・壁側の対応点。地面点は元々 z を決めていない (地面全除去でも同じ、§11.3)
│    ├── 効くレバー: 前処理の近傍点数 k_correspondences 10 → 20 で山が半分 (図 18)。GLIM 公式も 16 リングは 20 を推奨
│    ├── 効かないもの: IMU の内容・重み・重力方向 (R1/R2/R5)、GICP 反復数 (R10)、縦角表、時刻オフセット、extrinsic 回転、IMU バイアス固定 (§12.8)
│    ├── 生 IMU 自体のドリフト (§15、09-24): 生ジャイロに**旋回同期の傾き誤差 (新車体 6〜7°/90°、旧 1.3%)** と bias 変動 15〜25 mdeg/s が実在するが、届くのは姿勢まで。z 並進 A には届いていない (本命 — 根拠は R2/R5、ジャイロ置換 run E1 で確定させる)。加速度は run 内スケール一定
│    ├── 照合方式を GICP → VGICP に替えても z(s) の形は同じ k なら一致 (§12.9)。GPU 版も共分散は同じ k 由来なので、k を上げない限り同じ坂と予想 (本命・GPU 実走は未)
│    ├── IMU を外しても同じ坂 (CT-ICP、破綻前の直線で 80〜85%)。ただし CT-ICP は 90 m で破綻し運用不可 (§12.8)
│    └── 未解明: なぜ進行方向で符号が決まるか / なぜ走るほど・2 周目で 1.5 倍に育つか (§12.4 の A1/A2)
├── B. 壁抜け = 同じ柱を、時刻の違う submap が別の z に描く                 【本命】
│    ├── (i) 同一周内: 「前方 40 m から」「直上で」「振り返って」の 3 回で z が違う → 根元が地面板の下に出る (図 16)
│    ├── (ii) 周間: 2 周目が 1 周目より 2.6 m 高く重なる (図 14)
│    └── (iii) 誰も直さない: GLIM の自動ループ閉合は推定位置が 1 m ずれると発動しない (再訪問対の重なり 1〜3% < 閾値 20%、§12.2)
│         手動閉合は (ii) だけ消し、山と (i) は残る (§12.7、図 21・22)
├── C. 一定沈降 c ≈ −1°/経路長 (z_end の主因)                         【本命】= LiDAR–IMU 取付ピッチのずれ (旧車体 0.9° 実測) など。取付直しで改善済み
├── D. 外周だけの上乗せ: R-Fans 回転ディップの 5 s 欠落を IMU 単独予測で埋めて 11.5 / 32 m 飛ぶ   【確定、§13・別 issue】
│    └── k=20 では同じ欠落でも 17 → 7 m に縮む (欠落直前の odometry の質次第)。z 成分は acc_scale 0.985 で −2.6 → −1.2 m に半減 (|g| 不足が半分、確認済み。A と傾きには無効、§14.6)
└── E. global mapping 段が submap ブロックを IMU に逆らって傾ける (床の roll 歪み・螺旋面)        【計測は確定、機構は未識別、§14.4】
     ├── LiDAR 自身が見る地面は全 submap で平ら (±0.3°) → 床の傾き = global 段が submap に与えた回転そのもの
     ├── 後半 400 m のブロックが世界固定方向 (東北東) へ 8〜11° + 全周に進行方向左下がりの定数 roll −4° (k=10 では −8°)。BNO086 の実 roll は +0.5°
     ├── global 段の acc bias は ≤0.7° 相当 = IMU 因子が姿勢を重力に留めていない (critic H4 と整合)
     ├── pose-graph global (submap 間再登録なし) では傾き 0 = 再登録 (VGICP + between + IMU 境界因子) の中で起きる
     └── odometry 段でも姿勢が IMU に逆らって 1.4° 傾く (BNO086 は 0.2°、k で 1.8° に変わる = 推定器由来、§14.5)
```

## 5. まだ分からないこと

1. 進行方向で滑りの符号が決まる仕組み (単一方向の周回しか無く、場所と区別できない → 逆回り bag が要る)
2. 走るほど・2 周目で 1.5 倍に育つ仕組み (バイアス説は棄却。候補: odometry 状態の持ち越し / 経路差)
3. k=20 で残る半分の発生源 (法線の品質指標は k でほとんど変わらないので、単純な「面が決まらない」説では説明しきれない、図 19)
4. global mapping 段が submap ブロックを 8〜11° 傾ける機構 (§14.4 候補: VGICP の roll 縮退 / IMU 境界因子の実効重み不足 / between と VGICP の綱引き)。odometry 段の 1.4° 傾きとの関係
5. 同一 config でも odometry 段の山が run 間で 25 ↔ 35 m 動く (外周の run 間ノイズ床、§14.6)
6. 新車体の生ジャイロが旋回のたびに 6〜7° ずれる原因 (§15.2: BNO086 内部較正か、モータ電流の磁気外乱か。方向が 09-18 と 09-22 で反転)。これが §1 の旋回ピッチジャンプ・§14.5 の 1.4° 傾きの入力かどうか (E1 で判定)

## 8. 用語

- **A (heading 依存傾き)**: 直進区間の z 勾配を「一定 c + 進行方向の cos 成分 A」でフィットしたときの A。往路と復路で符号が反転する成分。
- **odometry 段 / global mapping 段**: GLIM の 2 段。前者はスキャン照合の生の軌跡 (`odom_lidar.txt`)、後者は submap 同士を最適化した最終結果 (`traj_lidar.txt`、viewer が表示するもの)。
- **implicit loop closure**: GLIM の閉合方式。場所認識は無く、推定位置で点群を重ねて 20% 以上重なった submap 対にだけ拘束を張る。位置がずれていると発動しない。
- **k_correspondences**: 前処理で各点の「面の向き」を推定するときに使う近傍点の数。旧 10、**現行 20 (09-21 変更)**。
