### 構成別 launch と出るトピック

自己位置推定の方式は **launch のファイル名で選ぶ**。先に第4章の `rerobot_bringup.launch.py` (全部入り) を上げておくこと。使い分けは [第15章](15_launch_guide.md)。

```
ros2 launch rerobot_bringup nav_amcl.launch.py map_dir:=/workspace/maps/2d/glim/<地図>
ros2 launch rerobot_bringup nav_amcl_scanall.launch.py map_dir:=... loc_map_yaml:=<map_dir>/loc_0.3-3.0/map.yaml
```

| launch | 自己位置推定 | 入力スキャン | 追加で出る topic | robot 側に必要なもの |
|---|---|---|---|---|
| `nav_amcl` | AMCL | `scan_topic` (既定 `/rfans/scan`) | `/amcl_pose`, `/particle_cloud` | 既定のままで可 |
| `nav_amcl_scanall` | AMCL (全点) | `/rfans/scan_all` (固定) | `/amcl_pose`, `/particle_cloud`, `/map_loc` (`loc_map_yaml` 指定時) | `rfans_scan_all:=true` |
| `nav_emcl2` | emcl2 | `scan_topic` (既定 `/rfans/scan`) | `/mcl_pose`, `/particlecloud`, `/alpha` | 既定のままで可 |
| `nav_lidar3d` | 3D (未実装) | — | — (起動するとエラーで止まる) | — |

`scan_topic` は **地図に合わせる**: GLIM 地図 = `/rfans/scan`、slam_toolbox 地図 (urg で作った地図) = `scan_topic:=/urg_front/scan`。

全構成に共通で出るもの:

| topic | 中身 |
|---|---|
| TF `map→odom` | 自己位置推定が出す (どの構成でも 1 つだけ) |
| `/map` | 経路計画用の地図 (`map_dir/nav2/map.yaml` または `map_yaml:=`) |
| `/keepout_filter_mask`, `/costmap_filter_info` | keepout (`use_keepout:=false` なら出ない) |
| `/global_costmap/costmap`, `/local_costmap/costmap` | costmap。障害物は `/urg_front/scan` と `/rfans/scan` の両方から書く |
| `/plan` | 大域経路 |
| `/robot_speed_cmd` | 速度指令 (Nav2 の `/cmd_vel` をリマップ) |
| (入力) `/initialpose` | RViz の 2D Pose Estimate |
| (入力) `/odometry/filtered`, TF `odom→base_link` | robot 側の EKF |

共通の引数: `map_dir` / `map_yaml` / `keepout_yaml` / `use_keepout` / `use_sim_time`。
従来の `nav2.launch.py` も使える。ただし `amcl_scan:=default` の入力は `scan_topic` (既定 `/urg_front/scan`)、
`all` / `far` は `/rfans/scan_all` / `/rfans/scan_far` に読み替わる (2026-10-08 の改名)。

### waypoint 走行 (事前に設定したコースを走る)

waypoint は **屋内で机上に打っておき**、当日は RViz で読み込んで走らせる。自作ノードは不要 — Nav2 標準の
**NavigateThroughPoses** (bt_navigator) と RViz Nav2 パネルの **Load WPs** だけで回る。

```
waypoint 走行の部品
├─ 作る:  tools/waypoint_editor (自作 GUI, rerobot_env)  地図の上でクリック → YAML 保存
├─ 読む:  RViz Nav2 パネル「Load WPs」                     YAML → 点列
└─ 走る:  NavigateThroughPoses (bt_navigator 既定 BT)
          ├─ RemovePassedGoals (radius 0.7 m)  通過した点を消す → 各点で止まらない
          └─ ComputePathThroughPoses           残りの全点を通る 1 本の経路を引き直す
```

ちなみに `nav2_waypoint_follower` (FollowWaypoints = 各点で一旦止まる方式) は `nav2.launch.py` に**入れていない**。
パネルの「Start Waypoint Following」は押しても失敗する。

#### 1. 机上で waypoint を作る (屋内)

```bash
xhost +local:docker   # ホスト。RViz と同じく X 表示に必要
docker exec -it rerobot_env python3 /workspace/tools/waypoint_editor/waypoint_editor.py \
  /workspace/maps/2d/glim/<map>/nav2/my_map.yaml \
  /workspace/maps/2d/glim/<map>/waypoints/<course>.yaml \
  --traj /workspace/maps/.../traj_lidar.txt      # 任意: 実際に走った線を重ねる
```

| 操作 | 動作 |
|---|---|
| 左クリック | 末尾に追加 |
| 点を左ドラッグ | 移動 |
| Shift + 左クリック | 最寄りの区間に挿入 |
| 右クリック | 削除 |
| Ctrl + 点を左ドラッグ | 向きを手動指定 (マウスの方向を向く。紫の矢印) |
| 点の上で `a` | 向きを自動 (次の点の方向) に戻す |
| `u` / `s` / `r` / `o` / `q` | 元に戻す / 保存 / 順序反転 / 通過半径の表示切替 / 終了 |

- 保存先が既にあれば読み込んで続きから編集。keepout は `<map_dir>/keep_out/keep_out.yaml` を自動で重ねる。
- 点の色: **緑 = 空き / 橙 = 未観測 / 赤 = 壁・keepout の上**。赤い点があると経路が引けず、走行全体が止まる (下の注意 ②)。
- yaw は既定で「次の点の方向」(青い矢印)。Ctrl + ドラッグで点ごとに手動指定でき、YAML に `yaw_manual: true` が付いて再編集でも残る。
  ⚠️ **NavigateThroughPoses で向きが効くのは最後の点だけ**。途中の点の向きは経路計算 (NavFn) に使われず通過するだけ。
  最後の点ではその場旋回して `yaw_goal_tolerance` (0.25 rad ≈ 14°) 以内に合わせて止まる。途中の点で向きを守らせたいなら
  FollowWaypoints (waypoint_follower を launch に追加、各点で止まる方式) が必要。
- GUI なしの確認: 末尾に `--check` を付けると全点の判定表を出す (要確認の点があれば exit 1)。出発前の最終確認に使う。
- ホストには matplotlib / tkinter が無いので、必ず rerobot_env で動かす。

保存形式 (パネルの Load WPs と同じ。orientation は **w が先頭**):
```yaml
waypoints:
  waypoint0:
    pose: [x, y, 0.0]
    orientation: [w, 0.0, 0.0, z]
```

#### 2. 当日に走らせる

1. bringup (IMU + EKF) を起動したうえで Nav2 を起動する。地図は **waypoint を打ったときと同じ地図**
   ```bash
   docker exec -it rerobot_env bash -c "source /workspace/install/setup.bash && \
   ros2 launch rerobot_bringup nav2.launch.py map_dir:=/workspace/maps/2d/glim/<map>"
   ```
2. RViz の「2D Pose Estimate」で AMCL の初期位置を合わせ、`/scan` が地図に重なることを確認
3. Nav2 パネル → **「Waypoint / Nav Through Poses Mode」** を押す (この状態でしか Load WPs は押せない)
4. **Load WPs** → YAML を選ぶ (地図上に点列が出る)
5. **「Start Nav Through Poses」**

RViz を使わず CLI で送る場合 (数点のテスト用):
```bash
docker exec -it rerobot_env bash -c "source /opt/ros/jazzy/setup.bash && \
ros2 action send_goal /navigate_through_poses nav2_msgs/action/NavigateThroughPoses \"{poses: [
 {header: {frame_id: map}, pose: {position: {x: 2.0, y: 0.0}, orientation: {w: 1.0}}},
 {header: {frame_id: map}, pose: {position: {x: 4.0, y: 1.0}, orientation: {w: 1.0}}}]}\" --feedback"
```

#### 注意 (既定 BT の弱点。2026-10-02 時点では BT XML を読んで推測しただけで、実走では未確認)

- ① **通過判定は 3 秒に 1 回**: RemovePassedGoals が `RateController hz=0.333` の中にある。1 m/s だと半径 0.7 m の円を約 1.4 s で
  抜けるので、判定の瞬間に円の外にいると点が消えずに**引き返す**恐れがある。出たら、BT XML を自作して
  RemovePassedGoals を RateController の外に出すか radius を広げ、`bt_navigator` の `default_nav_through_poses_bt_xml` に指定する。
- ② **1 点でも到達不能なら全体が中断**: 経路計算に失敗 → 復帰行動を最大 6 回 → abort。点ごとの「飛ばして次へ」はできない
  → waypoint_editor で赤い点を残さない。
- ③ **点ごとの処理は書けない** (信号待ちの停止・区間ごとの速度変更など)。必要になったら nav2_simple_commander で自作の送出スクリプトを作る。
- waypoint は**作成時の地図の map 座標**に紐づく。地図を作り直したら打ち直す (同じ bag・同じ dump から作り直しただけでも原点がずれうる)。

### bag からオフライン評価

自律走行 bag を再生して、`/scan` が `/map` にどう重なっていたか (= AMCL の推定がどれだけ合っていたか) を RViz で見返す手順。実機・Nav2・amcl は起動しない。

前提: bag に `/map` `/scan` `/tf` `/tf_static` が入っていること (第5章の Nav2 用 topic)。`/map` と `/tf_static` は transient_local のまま記録されるので、RViz を後から開いても地図は届く。

1. 準備 (ホスト)
```bash
xhost +local:docker
./scripts/stop.sh      # 実機スタック・amcl が動いていたら止める (bag の /tf と衝突する)
```

2. ターミナル A: RViz
```bash
docker exec -it rerobot_env bash
source /opt/ros/jazzy/setup.bash
rviz2 -d /workspace/src/bringup/rerobot_bringup/rviz/nav2.rviz --ros-args -p use_sim_time:=true
```

3. ターミナル B: bag 再生
```bash
docker exec -it rerobot_env bash
source /opt/ros/jazzy/setup.bash
ros2 bag play /workspace/bags/raw/<bag名> --clock --start-paused \
  --topics /tf /tf_static /map /scan /amcl_pose /plan \
           /local_costmap/costmap /local_costmap/published_footprint /odometry/filtered
```

| オプション | 意味 |
|---|---|
| `--clock` + RViz 側 `use_sim_time:=true` | **必ずセット**。片方だけだと TF の時刻が合わず `/scan` が「Message Filter dropping」で出ない |
| `--start-paused` | 停止状態で開始。B の端末で **スペース = 再生/停止、→ = 1 メッセージ送り** |
| `-r 0.5` | スロー再生 |
| `--topics ...` | 点群 `/rfans_driver/rfans_points` を流すと重いので絞る。`/initialpose` の再送も防げる |

見方:
- Fixed Frame は `map` のまま。`/scan` は **その時刻に AMCL が推定していた map→odom** で描かれるので、ずれ = AMCL 推定のずれ。
- LaserScan 表示の Decay Time: 0 で 1 スキャンずつ、数秒にすると残像が重なって系統的なずれが見やすい。
- bag に無いので空になる表示: `/particle_cloud`・global costmap・keepout mask・`/robot_description` (車体モデル)。エラー表示は無視してよい。
