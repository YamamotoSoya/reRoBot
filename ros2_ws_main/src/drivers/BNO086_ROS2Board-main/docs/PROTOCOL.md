# シリアルプロトコル仕様 (v2)

基板 (STM32F042) と PC (ROS 2 ノード) 間の通信フォーマットです。
USB CDC (`/dev/ttyACM*`) と USART1 (J4) のどちらでも同じフレームが流れます。

実装:
- 基板側 … `firmware/App/host_link.c` / `host_link.h`
- PC 側 … `ros2_ws/src/bno086_imu_driver/bno086_imu_driver/protocol.py`

## フレーム構造

```
+------+------+------+------+---------------+--------+
| 0xAA | 0x55 |  id  | len  | payload[len]  | crc16  |
+------+------+------+------+---------------+--------+
   0      1      2      3       4..4+len-1    2 bytes
```

- 全て **リトルエンディアン**
- `crc16` … CRC-16/CCITT-FALSE (多項式 `0x1021`、初期値 `0xFFFF`)。
  計算範囲は **`id` + `len` + `payload`** (同期バイトは含まない)。
  検査値: `crc16("123456789") == 0x29B1`
- `len` は payload のバイト数のみ

同期バイト列 `AA 55` は payload 中にも出現しうるため、受信側は
「同期一致 → 長さ読み → CRC 検証」で判定し、失敗したら 1 バイト進めて
再同期します (`FrameParser`)。

## センサ値のスケーリング

MCU 側では一切浮動小数点演算を行わず、BNO086 の固定小数点 (Q形式) を
そのまま転送します。実数への変換は PC 側の責務です。

| 項目 | 型 | Q | 係数 | 単位 |
|---|---|---|---|---|
| クォータニオン | int16 | Q14 | `2^-14` | (無次元) |
| 姿勢精度 | int16 | Q12 | `2^-12` | rad |
| 角速度 | int16 | Q9 | `2^-9` | rad/s |
| 加速度 | int16 | Q8 | `2^-8` | m/s² |
| 地磁気 | int16 | Q4 | `2^-4` | µT |

`sensor_msgs/MagneticField` はテスラ単位なので、ROS ノード側でさらに
`1e-6` を掛けています。

## 基板 → PC

### `0x01` IMU_DATA (payload 28 バイト)

| offset | 型 | 内容 |
|---|---|---|
| 0  | uint32 | 基板の起動からの経過時間 [µs] |
| 4  | int16  | クォータニオン i (Q14) |
| 6  | int16  | クォータニオン j |
| 8  | int16  | クォータニオン k |
| 10 | int16  | クォータニオン real |
| 12 | int16  | 姿勢精度 (Q12, rad) |
| 14 | int16  | 角速度 X (Q9) |
| 16 | int16  | 角速度 Y |
| 18 | int16  | 角速度 Z |
| 20 | int16  | 加速度 X (Q8) |
| 22 | int16  | 加速度 Y |
| 24 | int16  | 加速度 Z |
| 26 | uint8  | 精度ステータス (下記) |
| 27 | uint8  | 有効フラグ (下記) |

**精度ステータス (offset 26)** — BNO086 の accuracy を 2 bit ずつ格納。
値は `0`=unreliable / `1`=low / `2`=medium / `3`=high。

| bit | 内容 |
|---|---|
| 1:0 | 姿勢 |
| 3:2 | 角速度 |
| 5:4 | 加速度 |

**有効フラグ (offset 27)** — このフレームで更新された項目を示す。
BNO086 は項目ごとに異なるレートで報告できるため、常に全部が入るとは限りません。

| bit | 内容 |
|---|---|
| 0 | クォータニオン有効 |
| 1 | 角速度有効 |
| 2 | 加速度有効 |

無効な項目は ROS 側で共分散の先頭要素を `-1` にして「未提供」を明示します
(REP-145 の規約)。

### `0x02` MAG_DATA (payload 12 バイト)

| offset | 型 | 内容 |
|---|---|---|
| 0 | uint32 | 経過時間 [µs] |
| 4 | int16  | 地磁気 X (Q4, µT) |
| 6 | int16  | 地磁気 Y |
| 8 | int16  | 地磁気 Z |
| 10 | uint8 | 精度ステータス (0..3) |
| 11 | uint8 | 予約 (0) |

### `0x03` STATUS (payload 20 バイト)

1 秒ごとに自動送信されます。`PING` への応答としても返ります。

| offset | 型 | 内容 |
|---|---|---|
| 0  | uint32 | 経過時間 [µs] |
| 4  | uint16 | BNO086 の予期しないリセット回数 |
| 6  | uint8  | フラグ (下記) |
| 7  | uint8  | プロトコルバージョン (現在 `2`) |
| 8  | uint32 | 送信済み IMU フレーム数 |
| 12 | uint16 | BNO086 のリセット試行回数 |
| 14 | uint16 | SPI タイムアウト回数 |
| 16 | uint16 | 受信した SHTP パケット数 |
| 18 | uint8  | 直近のリセット到達段階 (下記) |
| 19 | uint8  | 予約 (0) |

**フラグ (offset 6)**

| bit | 内容 |
|---|---|
| 0 | IMU 応答中 |
| 1 | H_INTN が現在アサート (Low) |

**リセット到達段階 (offset 18)** — 立ち上げ時の切り分け用。

| 値 | 意味 | 疑うべき箇所 |
|---|---|---|
| 0 | 未実行 | — |
| 1 | H_INTN が一度もアサートされない | 電源 / NRST / PS0・PS1 ストラップ (JP1・JP2) |
| 2 | INT は来たが SPI がパケットを返さない | SPI 配線・モード・CS |
| 3 | パケットは来たが reset-complete が無い | SHTP 解析、プロトコル選択 |
| 4 | 正常 | — |

リセット回数が増える場合は電源品質を疑ってください。ファームウェアは
リセットを検出すると自動で購読を再設定します。

> 12 バイトしか返さない基板は v1 ファームです。ホスト側デコーダは
> 短いペイロードも受け付け、追加項目は 0 として扱います。

## PC → 基板

### `0x80` SET_RATE (payload 8 バイト)

| offset | 型 | 内容 |
|---|---|---|
| 0 | uint32 | IMU 報告間隔 [µs] (0 で停止) |
| 4 | uint32 | 地磁気の報告間隔 [µs] (0 で停止) |

例: 100 Hz なら `10000`、400 Hz なら `2500`。
BNO086 の最大レートは 400 Hz 程度です。

### `0x81` TARE (payload 1 バイト)

| offset | 型 | 内容 |
|---|---|---|
| 0 | uint8 | 1 なら Flash に保存、0 なら揮発 |

現在の姿勢を原点にします (SH-2 の Tare Now、全軸、Rotation Vector 基準)。

### `0x82` SAVE_DCD (payload なし)

動的キャリブレーションデータ (DCD) を BNO086 の Flash に保存します。

### `0x83` RESET_IMU (payload なし)

BNO086 をハードウェアリセットし、レート設定を再適用します。

### `0x84` PING (payload なし)

STATUS フレームを即座に返させます。

## 帯域

100 Hz 運用の場合:

```
IMU  : (28 + 6) バイト × 100 Hz = 3.4 kB/s
MAG  : (12 + 6) バイト ×  25 Hz = 0.45 kB/s
合計 : 約 3.9 kB/s
```

400 Hz でも約 14 kB/s なので、USB CDC でも 921600 bps の UART でも余裕があります。

## 既知の制約

- タイムスタンプは **BNO086 のサンプリング時刻ではなく、MCU がパケットを
  受け取った時刻** です。SPI の転送遅延 (数百 µs) は含まれません。
  SH-2 の report ごとの `delay` フィールドは現在使用していません。
- `uint32` の µs カウンタは約 71.6 分でラップします。PC 側 (`DeviceClock`)
  でラップを展開しているため、実用上の制限はありません。
- 送信バッファが溢れた場合、フレームは途中で切らずに **丸ごと破棄** します
  (途中で切ると受信側の同期が壊れるため)。
